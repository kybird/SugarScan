# 데이터셋 라이선스는 영수증→채널→상세 페이지 순서로 확인한다

제3자 데이터셋의 이용 조건은 한 곳에 있는 게 아니다. **확보 시점 영수증 →
배포 채널의 권리 구조 → 데이터셋 상세 페이지의 라이선스 문구** 순서로 내려가며
증거를 쌓는다. 어느 한 층만 보고 판정하면 틀린다.

## The Rule

1. **영수증(확보 시점)**: zip 안 README·라이선스 파일, 다운로드 기록. 배포자가
   누구인지의 1차 증거.
2. **채널의 권리 구조**: 배포처가 권리자인가? sugarScan 사례 — 지원사업 안내
   PDF 에 "소유권·저작권=수혜자, 공개·운영권=주최사" 조항이 있어서 S3 공개가
   권리자의 정식 배포임이 확인됐다. 리셀·무단 재배포 채널이면 이 층에서 걸린다.
3. **상세 페이지의 라이선스 문구**: 사이트 전역 문구(목적·소개)는 조건이
   아니다. **라이선스는 개별 데이터셋 상세 페이지에 있는 경우가 많다.**
   JS SPA 라면 기계(WebFetch·스냅샷·검색 스니펫)가 못 읽는다 — 브라우저로
   렌더된 페이지를 **사람 눈**으로 확인한다(사람이 마지막 한 칸을 닫는다).

조건이 확인되면 **의무 추적과 사실 기록을 분리해서 관리**한다: 의무(대기·확인·
제한)는 종결할 수 있지만, 출처·조건 사실 기록은 이용의 근거이자 남는 규칙의
자리라 유지한다("무료니까 기록 삭제"는 근거까지 지운다).

## Why it works

각 층이 서로를 교차검증한다. sugarScan 2026-10-10: 다운로드 기록(URL·용량) →
S3 HEAD(바이트 정합) → 버킷 리스팅(수혜자 구조) → PDF(권리 조항) → 상세
페이지(CC BY-SA 3.0 원문) — 다섯 층이 한 결론으로 수렴했다. 한 층(검색
스니펫의 "목적 제한 부 무료")만 봤다면 "재배포 문면 없음"이라는 오답으로
끝낸다(실제로 그렇게 틀렸다가 같은 날 정정됐다).

## Trade-offs

- 상세 페이지 확인은 사람 눈이 필요할 수 있다(JS SPA) — 기계 검증의 한계를
  보완하는 수단으로 사람 확인을 기록에 남긴다(누가·언제·어느 URL).
- 시간이 들지만, 소급 추적(다운로드 DB·Wayback)은 언제나 가능하다 — 처음부터
  아티팩트를 남기는 게 싸다.

## SA 안전판 (ShareAlike 데이터로 학습할 때)

CC BY-SA 로 공개된 데이터로 모델을 학습해 배포할 때 "가중치가 2차 저작물인가"는
법적으로 미해결이다. **모델 가중치의 저작권은 원래 학습자 것이므로, 가중치에
자발적으로 같은 CC BY-SA 를 표기하면 어느 독해가 맞아도 합치가 된다** — 2차
저작물이 아니면 자발적 라이선스일 뿐, 맞으면 SA 이행이다. 앱·코드는 폐쇄를
유지하고 가중치만 오픈 표기. 공개 저장소에 배포하는 프로젝트면 실비용이 0 이다.
BY(출처 표기)는 독해와 무관한 확정 의무 — 라이선스 화면 문구를 정해 두고
출시 체크리스트에 건다.

## Anti-Pattern

- 사이트 메인 문구를 라이선스로 오독(검색 스니펫만 믿고 "재배포 문면 없음"
  판정).
- 출처 없이 "구매 납품본" 식 주장 기록 → [[provenance-without-artifacts]].
- "무료"가 확인되면 기록에서 조건 행을 통째로 삭제 — 이용 근거까지 지운다.
