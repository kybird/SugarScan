# 프로젝트 자원과 브랜치 자원 — 저장 위치는 의미를 따라야 한다

저장소 안의 파일은 기본적으로 **브랜치 자원**이다. 브랜치를 바꾸면 내용이
바뀌고, 워크트리마다 사본이 생기며, 병합할 때 충돌한다. 그것이 옳은 값도 있고
치명적인 값도 있다.

## First Principles

질문 하나로 갈린다 — **이 값이 브랜치마다 달라도 되는가.**

달라도 되는 것(브랜치 자원): 소스 코드, 설정, 문서, 실험 스크립트. 브랜치는
"이 변경을 적용한 세계"를 뜻하므로 내용이 갈리는 것이 의미에 맞는다.

달라서는 안 되는 것(프로젝트 자원): 작업 보드, 클레임, 활동 로그, 사람이
붙인 라벨의 정본. 이것들은 "지금 무엇을 하고 있나"와 "무엇이 사실인가"를
담는다. 브랜치에 따라 달라지면 두 에이전트가 서로 다른 현실에서 일한다.

## Details

브랜치 자원으로 잘못 저장된 프로젝트 자원은 **조용히** 갈라진다. 양쪽 모두
정상으로 보이고, 충돌은 병합 시점에야 나타나며, 그때는 이미 어긋난 결정이
내려진 뒤다.

실제로 폐기한 카드가 부 워크트리에서 되살아나 있었다.
→ [[shared-state-split-by-worktree]]

버전 관리를 포기하지 않고 해결하는 방법이 있다: 파일은 저장소에 두되 **도구가
주 워크트리를 향하게** 한다. 그러면 물리적으로 한 벌이고, 커밋은 주 워크트리
에서 이뤄진다.

## 판별 질문

- 두 브랜치에서 이 값을 동시에 바꾸면 "둘 다 맞다"인가, "하나는 틀렸다"인가
- 병합할 때 이 파일이 자주 충돌하는가 (자주 충돌 = 공유 상태 신호)
- 이 값을 읽는 주체가 여럿인가, 그들이 같은 값을 봐야 하는가
