# 실험 예산 일치 — 두 팔이 같은 만큼 학습했는가

A/B 로 **구조**(프레이밍·전처리·아키텍처)를 비교하려면 두 팔이 같은 만큼
학습해야 한다. 예산이 다르면 표에 나오는 정확도 격차는 구조 효과와 수렴
부족의 **합**이고, 표는 둘을 구별해 주지 않는다.

## 왜 "하이퍼파라미터를 고정한다"로는 부족한가

코드를 고정하면 **두 팔 사이**의 동일성만 보장된다. 대조군이 코드 밖에서
만들어졌다면 — 사람이 재시작을 거듭하며 키운 모델이라면 — 코드를 고정해도
대조군과는 안 맞는다.

이 저장소에서 실제로 일어난 일:

| | 파인튜닝 에폭 | 최종 손실 | 완전일치 |
|---|---|---|---|
| 기준선 `reader_model` | **60** (재시작 7회 누적 로그의 마지막 런) | 0.1238 | 97.06% |
| 크롭 팔 (G30) | 12 (스크립트 기본값) | **0.96** | 87.79% |
| 같은 크롭 팔, 예산만 맞춤 (G31) | 60 | 0.1095 | **95.72%** |

**에폭 하나로 격차 9.27pp 중 7.93pp 가 사라졌다.** G30 의 표는 프레이밍의
성적이 아니라 수렴의 성적이었다.

지시서에는 "에폭 수를 건드리지 말 것"이라고 적혀 있었다. 그 말이 가리킨
스크립트 기본값(40+12)이 대조군의 실제 예산이 아니었을 뿐이다.

## 대조군의 실제 예산을 찾는 법

예산이 코드에 없고 **로그에만** 있을 수 있다.

```bash
ls -lad reader_model training_log.csv          # mtime 이 같아야 그 모델의 로그다
awk -F, 'NR>1 && NF==2' training_log.csv | wc -l   # 320행 = 재시작 누적
awk -F, 'NR>1 && NF==2{if($1==0){n=0}; a[++n]=$2} END{print n, a[n]}' training_log.csv
```

`epoch` 열이 0 으로 되돌아가는 지점마다 런이 갈린다. 누적 행 수가 아니라
**마지막 런의 길이**가 대조군이 받은 예산이다(각 런이 사전학습 best 에서
다시 시작하는 구조라면).

## 점검 체크리스트

- [ ] 대조군의 예산을 **로그에서 확인**했는가. 스크립트 기본값으로 추정하지 않았는가
- [ ] 로그가 그 모델의 것인가 (모델 폴더와 mtime 대조)
- [ ] 지시서에 새 팔의 에폭 수를 **숫자로** 적었는가. "기본값 그대로"라고 쓰지 않았는가
- [ ] 보고서에 **양쪽의 최종 손실을 나란히** 적게 했는가 — 예산이 맞았는지 사람이 표 한 줄로 본다
- [ ] 예산 끝에서 손실이 하강 중이면 그렇게 적고 멈추게 했는가 — 에이전트가 스스로 늘리면 반대 방향으로 깨진다
- [ ] 중간에 죽었을 때 **이어붙이지 말고** 처음부터 다시 돌리게 했는가 — 재시작 누적이 바로 이 문제를 만든다

## 예산이 맞았는지 확인하는 신호

최종 손실이 대조군과 같은 자리수면 예산이 맞은 것이다. 새 팔의 학습 손실이
대조군보다 **낮은데** 홀드아웃이 나쁘면 그건 수렴 부족이 아니라 진짜 격차다
(G31: 0.1095 vs 0.1238 인데 95.72% vs 97.06%). 이때는 에폭을 더 늘리지 않는다.

## 기전과 결과가 어긋날 때

G30 에서 크롭은 세로만 자르므로 가로 해상도 = CTC 타임스텝 40 을 건드리지
않는다. 직전 실험(letterbox)이 세운 기전으로는 **유리해야 하는** 팔인데 더
못 맞았다. 기전과 결과가 어긋나면 결과를 믿기 전에 실험 설계를 의심한다 —
이 경우 예산이었다.
