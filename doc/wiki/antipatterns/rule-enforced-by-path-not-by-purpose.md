# 규칙을 **경로**로만 지키면 다른 경로로 샌다

"실사진을 커밋하지 않는다"를 `gitignore` 한 줄로 지키면, 사진이 **다른
형식으로 다른 경로에** 들어오는 길은 열려 있다. 규칙은 경로가 아니라
**용도**로 적어야 한다.

## 실패 모드

데이터 폴더는 막혀 있으니 점검도 그 폴더만 본다. `git ls-files <데이터폴더>`
가 0건이면 "지켜지고 있다"로 끝난다. 그런데 **비교 그림·몽타주·검수 시트**는
실사진을 합성과 나란히 놓는 것이 목적이라, 구조적으로 사진을 문서 폴더로
옮긴다. 그리고 그건 PNG 한 장이라 파일 수로도 크기로도 눈에 안 띈다.

## 사례

2026-09-20, 공개 저장소 점검. `git ls-files assets_dev/upstream` 는 **0건**
이었다 — 데이터 폴더 규칙은 지켜지고 있었다. 추적 중인 이미지는 26개였고
23개가 앱 아이콘, 나머지 3개 중 2개가 그래프였다. **세 장을 다 열어 본 뒤에야**
`docs/reports/profile-expansion-compare-2026-09-12.png` 안에 Datumo 실사진
크롭 6장이 들어 있는 것을 찾았다. 파일명(`profile-expansion-compare`)만으로는
합성끼리의 비교로 읽힌다. 공개 저장소에 일주일 올라가 있었다.

## 예방 체크리스트

- 규칙을 **용도**로 적는다: "조건 미확인·귀속 의무 있는 실사진은 **학습 금지,
  검증만 허용**. 이미지는 어떤 형식으로도 커밋하지 않는다."
- 점검을 **경로가 아니라 파일 종류**로 한다. 추적 중인 이미지를 **전부 세고**,
  앱 자산이 아닌 것은 **연다.** 이름으로 판정하지 않는다.
- 비교 그림을 만들 때 **실사진 쪽은 저장소 밖 뷰어로 보낸다**(웹툴 등).
  문서에는 합성과 수치만 남긴다.
- 가능하면 **구조로 막는다.** 데이터를 저장소 밖에 두고 정션·심링크로
  경로만 유지하면, 실수로 커밋될 여지 자체가 사라진다.
