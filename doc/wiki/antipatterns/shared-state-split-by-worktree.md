# 프로젝트 전체가 공유해야 할 상태를 브랜치 안에 저장하는 것

작업 보드·클레임·활동 로그는 "어느 브랜치에서 보든 같아야" 하는 값이다.
그런데 그것을 저장소 안의 추적 파일로 두면 git 워크트리마다 사본이 생긴다.
두 에이전트가 다른 브랜치에서 일하는 순간 **서로 다른 보드**를 본다.

## 실패 모드

한 저장소에 링크 워크트리가 여럿 있는 상태에서:

```
주 워크트리   TODO 9 · done 18 · abandoned 3
부 워크트리   TODO 2 · done 21 · abandoned 2
```

부 워크트리 TODO 에 **주 워크트리에서 폐기한 카드**가 살아 있었다. 에이전트가
그것을 집으면 폐기된 일을 한다. 반대로 주 워크트리에 세운 카드 7장이 부
워크트리에서 보이지 않았다. `doc/kanban/activity.jsonl` 은 병합할 때마다
충돌했다(같은 날 두 번).

증상이 조용하다는 것이 핵심이다. 두 보드 모두 정상으로 보인다.

## 왜 이게 반복되는가

카드를 파일로 두는 것에는 좋은 이유가 있다 — 버전 관리, 리뷰, 되돌리기.
그래서 "저장소 안"이 자연스러운 선택이 된다. 워크트리는 나중에 생긴다.

그리고 도구가 cwd 에서 위로 올라가며 설정 디렉터리를 찾는 관례를 따르면,
링크 워크트리에서는 **그 브랜치 사본에서 멈추는 것이 당연한 동작**이 된다.
버그처럼 보이지 않는다.

## 점검 체크리스트

- [ ] 이 상태가 브랜치마다 달라도 되는 값인가, 프로젝트 전체에서 하나여야 하는가
- [ ] 워크트리를 두 개 만들어 같은 명령을 돌려 봤는가 — 결과가 같은가
- [ ] 병합할 때마다 충돌하는 파일이 있는가. 있다면 그게 공유 상태 신호다
- [ ] 도구가 루트를 cwd 기준으로 찾는가, 저장소 기준으로 찾는가

## 무엇을 해야 하나

**저장 위치를 의미에 맞춘다.** 공유 상태는 워크트리와 무관하게 한 곳을 향해야
한다. git 저장소라면 주 워크트리를 기준점으로 쓸 수 있다 —
`git rev-parse --git-common-dir` 의 부모가 주 워크트리 루트다.

부작용은 명시해야 한다: 부 워크트리에서 실행한 쓰기가 주 워크트리의 파일을
바꾼다. 그 변경은 주 워크트리에 미커밋으로 남고 거기서 커밋된다. 이것은
버그가 아니라 의도한 동작이며, 문서에 적지 않으면 다음 사람이 놀란다.

되돌릴 길(옵트아웃)을 남긴다 — 종전 동작에 기대던 사용자가 있을 수 있다.
