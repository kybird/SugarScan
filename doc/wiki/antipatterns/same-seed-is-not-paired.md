# 코드를 고친 뒤의 **같은 시드**를 짝지은 비교로 읽는 것

"같은 시드로 돌렸다"는 재현성 문구는 **코드가 그대로일 때만** 짝지음을 뜻한다.
코드를 고친 뒤의 같은 시드는 재현이지 짝지음이 아니다.

## 실패 모드

단일 난수 스트림을 여러 축이 나눠 쓰면, 한 축의 **소비 개수**가 바뀌는 순간
그 뒤의 모든 뽑기가 밀린다. 같은 시드라도 **다른 장면**이 나온다.

sugarScan 2026-09-16: 합성기의 반사를 한 종류에서 세 종류로 늘린 뒤,
같은 시드(777001)·같은 장수(300)로 검증기를 돌려 전후를 견줬다.

```text
gpc 0.9 미만   변경 전 6.0%  →  변경 후 7.7%
```

이걸 "반사를 넣으니 글리프 평면이 나빠졌다"로 읽을 뻔했다. 그런데 새 코드는
패치마다 뽑는 난수 개수가 달라서, 두 실행은 **같은 장 300개의 전후가 아니라
서로 다른 장 300개**였다.

## 어떻게 드러났나

변경 뒤 세 시드에서 재니 7.7 / 10.0 / 10.0% 였다. 시드 간 흔들림이 그 정도인데
변경 전 표본은 하나뿐이었다. **비교할 수 있는 상태가 아니었다.**

## 점검 체크리스트

- [ ] 비교하려는 두 실행 사이에 **난수를 소비하는 코드**가 바뀌었는가
- [ ] 바뀌었다면 두 실행이 같은 표본을 보는가 — 파일명·해시로 확인했는가
- [ ] 짝지음이 깨졌다면 **주장을 낮췄는가**(방향만 말하고 크기는 말하지 않음)
- [ ] 아니면 짝지을 수 있는 설계로 바꿨는가(같은 입력을 두 코드에 통과시키기)
- [ ] 층별 중앙값만 보지 않고 **승·패·무**를 세었는가 — 짝지어야 셀 수 있다

## 왜 반복되는가

시드를 고정하는 습관이 **재현성**을 위한 것인데, 그 습관이 **비교 가능성**까지
보장한다고 착각하기 쉽다. 둘은 다른 성질이다. 재현성은 "같은 코드+같은 시드 →
같은 결과"이고, 짝지음은 "두 조건이 같은 표본을 본다"이다.

## 짝지을 수 있을 때는 반드시 짝짓는다

같은 체크포인트·같은 사진에 전처리만 다르게 돌린 경우처럼 짝지음이 성립하면
**승·패·무**를 센다. 층 중앙값 하나로 판정하면 이상치 한 장이 평균을 끌고 가는
것을 축의 효과로 읽는다(2026-09-17 Case 1: 가로 42장에서 무승부 23, 평균은
한 장이 만들었다).
