# 버스트 코퍼스를 이미지 단위로 랜덤 분할하는 것

같은 촬영 세션(같은 기기·구도·조명)의 사진이 여러 장 있는 코퍼스를 이미지 단위로
섞어 train/holdout 을 가르면, **모델이 시험에서 다시 보는 장면**을 학습에서 이미
본 상태가 되고 지표가 인플레이션된다.

## 실패 모드

`build_cache_v2.py:169-176` 이 GM 쿼드 풀 2,494장을 `RandomState(123)` 이미지
단위 셔플로 갈랐다. dhash(해밍 ≤8) 연결요소로 장면을 계측하니:

- 교차 분할 근접쌍 **9,068쌍**, 홀드아웃 **73.7%(827장)** 이 train 과 같은 장면
  성분, **45.1%(506장)** 은 같은 장면+같은 표시값까지 공유.
- 층별 재집계(재학습 없음): 완전 clean **94.24%**/위험 1.69% → 장면 누수만
  97.20% → 값 누수 **98.62%**/위험 0.40%. **누수가 클수록 점수가 오르는 단조
  기울기가 누수의 서명이다.**
- 기준선 97.06%/0.98% 는 폐기, 세션 무결 재분할 재학습으로 96.67%/1.51%.

**이 안티패턴의 함정은 누수 자체가 아니라 누수 검사의 오답이다.** 두 번(2026-09-04,
2026-09-09) 모두 "세션 = 연속 촬영 번호"라는 나이브 프록시로 먼저 검사했고 둘 다
놓쳤다:

- 9/4: "holdout 의 id 이웃(±1) 중 GT 까지 같은 장은 6건 — 무시 가능" 으로 종결.
- 9/9: 연속번호+같은값 런이 12개뿐 → 누수 0.6% 로 보임.
- 실제: 촬영자가 **같은 구도에서 값만 바꿔가며 반복 촬영**했다. 세션은 번호
  순서가 아니라 **장면**이며, 근접쌍의 id 거리는 3~25까지 흩어져 있다(1023↔1027
  몽타주: 같은 기기·각도, 표시값 156→90, GT 일치).

**질이 다른 두 검사가 같은 "확인했음"으로 기록된다.** 프록시로 돌린 검사는
"누수 없음"을 증명하는 게 아니라 "그 프록시로는 안 잡힌다"만 증명한다.

## 점검 체크리스트

- [ ] 분할 단위가 **촬영 세션/물리 기기**인가 — 이미지 단위 랜덤 셔플이면 이
      페이지를 먼저 읽었는가
- [ ] 세션의 정의를 **메타데이터가 아니라 픽셀 유사도로 검증**했는가
      (dhash·pHash 근접쌍 연결요소; 무작위쌍 평균 해밍과의 대비)
- [ ] 교차 분할 성분이 **0임을 assert** 하는가 (사람 눈이 아니라 스크립트로)
- [ ] 누수 층별 재집계에서 **단조 기울기**가 없는지 봤는가
- [ ] "id 인접±N" 같은 프록시로 누수 없음을 말하고 있지 않은가 — 프록시 부정
      결과는 결론이 아니라 프록시 기각이다
- [ ] 분할을 고친 뒤 기존 기준선 인용을 전부 폐기했는가

## 왜 이게 반복되는가

누수는 학습·평가 어느 쪽에서도 에러를 내지 않는다 — **점수가 좋게 나오기
때문에** 아무 알람이 울리지 않는다. 의심이 드는 순간은 "너무 좋다"를 볼 때뿐인데,
그 순간에도 세션을 잘못 정의하면(연속번호) "문제없음"이라는 그럴듯한 답을 얻고
넘어간다. 검증은 세션 정의 자체를 픽셀 증거로 대체해야 끝난다.
