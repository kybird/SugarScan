# 렌더 결과 검증을 비전으로 하면 환각이 돌아온다 — 코드와 픽셀로 답한다

"그림이 이상하다"는 사람 관찰에 비전 재검증으로 맞서면, 비전은 선행 프롬프트에
끌려 내 그림을 "설명해 주는" 방향으로 환각한다. 정답은 코드 경로를 읽고 그린
색의 픽셀을 계산하는 데 있다 — **기록·인상이 아니라 원본 증거(픽셀 실측)로
답한다.**

## 실패 모드

sugarScan 2026-10-07: 사람 보고 "상자가 화면 좌상단에 작게 그려져 있다",
"숫자를 감싼 라벨은 하나도 없다". 나는 ①내 그림을 비전에 재검증("정상 감쌈" —
환각) ②EXIF/프레임 이론 ③뷰어 캐시 이론 ④채팅 미리보기 이론으로 **2시간 사람
말을 이겨보려 했다.** 범인은 한 줄이었다:

```python
# 잘못: 풀해상도 크롭에 타일 축척 좌표로 그린 뒤, 크롭 전체를 다시 resize
sx = TILE_W / crop.shape[1]
cv2.rectangle(crop, (int((p[0]-cx0)*sx), ...), ...)   # ← 이미 축소된 좌표인데
tile = cv2.resize(crop, (TILE_W, hh))                  # ← 한 번 더 축소 (×sx²)
# 수정: 축소를 먼저 하고 그린다 (draw-after-resize)
tile = cv2.resize(crop, (TILE_W, hh))
```

사람 스크린샷을 분석한 비전은 정확했고, 내 그림을 넣은 비전은 내 프롬프트에
동조해 거짓을 답했다 — **같은 도구가 입력에 따라 진실/환각을 갈라 놓은 것.**

## 점검 체크리스트

- 사람이 "그림/출력이 이상하다"고 하면: (1) 해당 그리기 코드 경로를 그대로
  읽고 (2) 그린 색의 픽셀 bbox 를 numpy 로 재서 기대 위치와 대조한다.
- **비전은 사람 스크린샷 해석에만 쓰고, 내 산출물 검증에는 쓰지 않는다.**
- 사람 관찰 vs 내 측정이 충돌하면 사람 관찰을 기준으로 내 쪽에서 어긋난
  지점을 찾는다. 이론을 나열하며 사람을 설득하려 들지 않는다.
- cv2(BGR)+PIL(RGB) 조합의 rectangle 색 순서 실수는 하루 세 번 냈다 — 판
  스크립트는 그린 뒤 색 픽셀 유무·bbox 를 코드로 assert 한다.
- 좌표 변환 계층이 둘(그리기 축척·리사이즈)이면 **축소 먼저, 그리기 나중**.
  draw-after-resize. 리사이즈 뒤 tile 크기로 좌표를 다시 계산한다.

## 왜 반복되는가

픽셀 계산은 프롬프트에 반응하지 않고, 비전은 선행 맥락("초록=라벨이니 감싸겠지")에
끌려 그림을 정당화한다. 사람 관찰과 내 측정이 충돌하는 순간, 이론을 나열하는 쪽은
거의 항상 틀린 쪽이다.
