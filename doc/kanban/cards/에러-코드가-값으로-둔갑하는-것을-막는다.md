## Goal
<!-- kanban:goal:begin -->
혈당계의 E-1 같은 에러 표시가 ReadingNormalizer 에서 숫자로 정리되는 것을 막는다. 판정을 HI/LO 와 같은 구간(글자 교정 앞)에 넣어 UnreadableReading 으로 떨어뜨린다. 상태로 기록하지 않는다 — 에러 코드는 혈당 정보가 없고 의미가 제조사마다 다르다.
<!-- kanban:goal:end -->

## Acceptance Criteria
<!-- kanban:ac:begin -->
- [ ] #1 E-1~E-9 · ER · ERR · ERR-5 · ERROR2 가 NormalizedNumber 로 나오지 않는다
- [ ] #2 mmol/L 로도 GlucoseValidator 를 통과하지 않는다 — mg/dL 만 테스트하면 하한 10 이 우연히 막아 버그를 숨긴다
- [ ] #3 회귀: HI · LO · H1 · HIGH · LOW 가 종전대로 MeterRangeReading, 138 mg/dL → 138, 7.6 mmol/L → 7.6
- [ ] #4 경계: 123E 는 123 으로 남고, E 단독 · E- 는 UnreadableReading 이다
- [ ] #5 판정이 글자 교정(③) **앞**에 있다 — 보고서가 코드 인용으로 보인다
- [ ] #6 flutter analyze 무경고 + flutter test 전체 통과

## Plan
1) reading_normalizer.dart 의 normalize() 에 에러 코드 판정을 넣는다. 위치가 이 작업의 전부다 — 반드시 ② HI/LO 판정과 같은 구간, ③ 글자 교정 앞. ③ 뒤에 두면 이미 '1' 이 되어 있어 아무것도 못 잡는데 테스트는 통과한다. 기존 ①②③ 주석과 같은 톤으로 이유를 적을 것.
2) 판정 대상은 compact(공백 제거·대문자화) 기준으로 정확히 셋. ^E-?\d{1,2}$ · ^ER{1,2}-?\d{0,2}$ · ^ERROR\d{0,2}$. ^$ 를 반드시 붙인다 — 부분 일치로 넓히면 정상 판독을 삼킨다.
3) 반환은 기존 UnreadableReading. 새 sealed 서브클래스를 만들지 말 것 — ScanOutcome·확인 시트·l10n·통계까지 파급되는데 방침이 '값이 아니다' 라 기존 실패 경로가 이미 옳다.
4) 테스트는 test/ocr/ 의 기존 정규화 테스트 파일에 붙인다(새 파일 금지). 테스트 이름은 한국어, 기존 문장 스타일.

건드리지 말 것: glucose_validator.dart 0줄(범위 상수 포함 — 에러 코드 지식은 혈당 도메인이 아니라 7-세그먼트 판독 특성이다) · ocr.dart 배럴 · ScanOutcome · 확인 시트 · l10n ARB 6개 0줄(새 사용자 문구가 필요 없는 설계) · _confusions/_unitTokens/_high/_low 기존 항목 · ①②③ 순서 자체 · assets_dev/ 전부.

틀리기 쉬운 자리: ③ 뒤에 넣기(테스트는 통과하고 아무것도 안 막힌다) · 정규식에 ^$ 빠뜨리기 · mg/dL 로만 테스트하기 · 테스트에서 lib/ocr/src/ 직접 import(경계 위반 — lib/ocr/testing.dart 경유).

## Notes
- 2026-09-10T11:11-07:00 — 왜 지금인가 — 'CTC 탑재 전 결정' 이 아니라 이미 뚫려 있다. 규칙 엔진은 소수점을 읽어 mmol/L 사용자에게 적용된다. 실측: E-1 → 정규화 '1'. mgdlMin=10 이라 mg/dL 은 거절되지만 mmollMin=0.6 이라 mmol/L 은 1.0 이 통과하고, E-5 는 5.0 mmol/L 이라는 완전 정상값으로 저장된다. LO→10 과 같은 계열이며 단위 비대칭이라 더 나쁘다 — mg/dL 로 테스트하면 안 잡힌다. 실사진이 필요 없어 mmol 데이터 확보를 기다리지 않고 지금 진행할 수 있다.
