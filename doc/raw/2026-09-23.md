2. 라벨러 '판독 실패' 큐 필터(reader/risky/safe/blank/rejected)와 화면의 CTC

3. 훈련 탭 '학습 시작' 버튼 — 폐기 계열 `train_band_detector.py`(GM 크롭·

### Analysis
- Why non-obvious: 폐기 결정은 "실험 수치를 인용하지 않는다"는 규칙으로
  나타났지 "폐기 모델의 산출물을 뿌리는 코드를 끊는다"는 규칙으로 나타나지
  않았다. 수치는 문서에 있어 찾기 쉽지만, 화면·버튼·큐는 **돌아가는
  코드**라 살아 있는 것처럼 보인다 — 잘못된 근거로도 완벽하게 동작한다.
- Impact: 사람의 라벨링 우선순위(2번)가 옛 모델 오답에 매여 있었고, 사용자가
  보던 "기종 탭 예측"이 정본 검출기의 것이 아니었다.
- Action taken: 전부 끊었다(커밋 541d1de, +180/−696). 오버레이는 atone_s0 로
  재덤프(2,512장, conf<0.25 버림 0). 폐기 계열 파일(reader_preds.json 등)은
  디스크에 남기되 읽는 화면을 0개로 만들었다. WEBTOOL.md 화면 지도를 같이
  갱신 — 화면의 데이터 원천이 배치 산물인 이상 "낡은 걸 화면이 숨긴다"는
  원칙이 이 사고의 예언이었다.
- 폐기 계보의 **데이터**(사람 라벨, GM 쿼드의 라벨 힌트 용법)는 유지했다 —
  모델이 폐기됐다고 사람이 그린 정답까지 버리는 게 아니라, 폐기 모델의
  **예측**을 현재처럼 보여 주는 표면만 없애는 것이 기준선이다.
