## [2026-11-17 discovery] Case 1: 합성기 LCD 요소 렌더링의 3갈래 경로와 확률 게이트

### 검색 단서
합성기 레이아웃, 프로파일 unit, 와이드 칼럼, 하단행형, 세로형, _wide_t,
_shown, p, 확률 게이트, CODE 렌더 실패, unit rect 누락

### Grounding
- Git Context: `hash:6aded72`
- Evidence: debug 로그(rects 덤프) — onetouch_ultramini p=0.7 시 unit rect 부재
- Confidence: 5/5

### 발견

LCD 보조 요소(unit·time·date·mem·glulabel)는 **3갈래 경로**로 나뉘며,
각 경로에 독립적인 확률 게이트가 있다:

```
1. 와이드 칼럼형  _wide_t is not None and _wide_t[0] < 0.75
   게이트: _shown("wide:unit", 0.8) + profile.unit.p
   조건: _cw > 26 (칼럼 최소 폭)
   실패 시: 아무 대체 없이 스킵

2. 와이드 하단행형  _wide_t is not None and _wide_t[0] >= 0.75
   게이트: rng.random() < 0.85 (unit), 0.8 (time)
   위치: 밴드 안 하단행 (qx0..qx1)

3. 세로형  _wide_t is None
   게이트: _shown("unit", profile.unit.p)
   위치: pos 필드에 따라 (below-center / below-right / right-of-digits 등)
```

**경로 간 이동 없음**: 칼럼에서 실패해도 하단행·세로형으로 물러나지 않는다.
와이드 칼럼의 `_cw <= 26` 이면 요소가 **세 경로 모두에서 떨어진다**.

확률 게이트가 **2중으로 겹친다**: profile.unit.p(기본 0.7) ×
_shown("wide:unit", 0.8) = 표시율 56%. 코드 화면처럼 "반드시 보여야
하는" 요소는 p=1.0 + 게이트 우회가 필요하다(2026-11-17 수정).

### 분석
이 구조는 기기 다양성(모든 기기가 같은 요소를 같은 자리에 보이지 않는다)을
위한 것이다. 하지만 요소가 화면의 **유일한 구분 신호**일 때(CODE 라벨)는
확률 게이트가 결함이 된다 — " 있어도 없어도 되는 요소"와 "없으면 안 되는
요소"를 가르는 수단이 없다.

### 조치
코드 화면에서 unit.p=1.0 강제 + _shown("wide:unit") 우회(6aded72).
범용 해법은 아니다 — "필수 요소" 선언机制가 없어 프로파일별로 판단한다.
