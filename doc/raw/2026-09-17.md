# 2026-09-17

## Case 1: 층 중앙값 하나로 축을 판정했다가 이상치 한 장을 원인으로 보고했다

### Grounding
- Evidence: `docs/reports/gm-preproc-letterbox-ab-2026-09-16.md` 「2026-09-17 정정」절 ·
  `assets_dev/train/gm_preproc_ab.py` `--paired` ·
  `assets_dev/train/diag_gm_candidate_tie.py`
- Confidence: 5/5

### Discovery
전처리 A/B 에서 채널 축(학습 BGR / 추론 RGB)을 고친 팔이 **가로 층에서 나쁘다**
고 보고했다. 근거는 층별 IoU 중앙값(0.799 → 0.768)과, 한 장이 0.526 → 0.039 로
무너진 것이었다. 그 장을 "채널 축의 불안정성"이라고 적었다.

사람이 물었다 — **"채널순서가 죽은건 왜그렇지 화일포맷문제냐 우리 리더가
일관성이 없는거냐?"** 답하려고 재 보니 내 귀속이 틀렸다.

짝지어 보면(같은 장, 같은 체크포인트, 전처리만 다름):

```text
전체 n=405  승 161 · 패 95 · 무 149  중앙 +0.0032  평균 +0.0080
가로 n=42   승  5 · 패 14 · 무  23  중앙 -0.0044  평균 -0.0195
세로 n=363  승 156 · 패 81 · 무 126  중앙 +0.0054  평균 +0.0112
```

가로는 **절반 이상이 무승부**이고 중앙값과 평균이 다섯 배 갈린다 — 꼬리가
평균을 끌고 있다는 신호다.

### Environment Context
- Packages: sugartrain · YOLOX
- Migration Issue: No

### Analysis
- Root cause(보고의): n=45 짜리 층의 **중앙값 하나**로 축을 판정했고, 그 층에
  이상치가 하나 있다는 사실을 함께 보지 않았다. 승·패·무를 세었으면 무승부
  23/42 가 먼저 보였을 것이다.
- Root cause(현상의): 무너진 장은 채널과 무관했다. 두 전처리의 입력이 픽셀
  평균 **3.37/255** 밖에 안 다르고, 그 사진은 |R−B| 평균 **6.7** 로 거의
  무채색이라 R↔B 를 바꿔도 화소가 안 변한다. 진짜 원인은 **후보 두 개가
  0.3% 차이로 붙어 있는데 넓이가 33.5배 다른 것**이다 — 기기 전체
  2417×2920 과 작은 조각 463×455. 무엇이든 조금 흔들면 top-1 이 뒤집힌다.
- 대조군: 같은 방식으로 1598 을 보면 입력 차가 더 큰데도(12.98) 1위가 77% 차로
  명확해 상자가 안 뒤집힌다. 즉 "입력이 달라서"가 아니라 "모델이 못 정해서"다.
- How it was fixed: 보고서에 정정 절을 붙이고, 자에 `--paired` 를 넣어 승·패·무
  와 꼬리 이름을 같이 찍게 했다. 카드 Result 에도 정정 노트를 달았다.
- 같은 날의 거울: Case 9 는 **문턱 세기가 연속량의 이동을 삼키는** 반대 방향을
  지적했다. 한쪽에서 집계의 함정을 잡아 놓고 다른 쪽에서 반대 함정에 빠졌다 —
  요약 통계 하나로 판정하지 않는다는 규칙이 두 방향 모두에 적용된다.
