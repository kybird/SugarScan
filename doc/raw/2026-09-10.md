## Case 1: tf2onnx 설치가 훈련 환경의 TF 임포트를 죽였다 — numpy 2.x 가 진벽

### Grounding
- Git Context: `hash:ca4a49c`
- Evidence: `docs/reports/reader-onnx-parity-2026-09-10.md` §환경 사고·복구 기록 ·
  `assets_dev/train/reader_onnx_spec.md` 말미
- Confidence: 5/5 (재현·복구·검증을 이 밤에 전부 수행)

### Error
sugartrain(TF 2.10.1) 환경에서 `pip install tf2onnx`(최신) 후
`import tensorflow` 가 즉사:

```text
_np_bfloat16 = _pywrap_bfloat16.TF_bfloat16_type()
TypeError: Unable to convert function return value to a Python type!
The signature was () -> handle
```

### Environment Context
- Packages: tensorflow 2.10.1 · tf2onnx(최신 → 1.12.0) · protobuf 7.36.1 로 상승 ·
  **numpy 2.2.6 로 상승(원인)** · onnx 1.12.0 으로 하강(부수)
- Migration Issue: No (신규 패키지 도입의 부수효과)

### Fix Code
```text
복구 조합(전부 만족해야 함):
  numpy==1.23.5        # TF 2.10 은 numpy 2.x 에서 위 TypeError 로 죽는다
  protobuf==3.20.3     # 신·구 pb2 를 모두 지원하는 다리 버전(3.19 는 onnx 신스타일 거부, 4.x 는 TF 거부)
  onnx==1.13.0         # 1.22+ 는 numpy>=1.25 요구 → TF 2.10 과 양립 불가
  tf2onnx==1.12.0
  onnxruntime==1.23.2  # 기존 유지
검증: 네 모듈 임포트 + 미니 Keras fit(TRAIN OK)
```

### Analysis
- Root cause: **pip 의존성 해결기가 '요구를 만족하는 최신 조합'을 찾을 뿐 '기존
  워크로드가 돌아가는 조합'을 보존하지 않는다.** tf2onnx 최신은 protobuf>=3.20 을
  요구해 체인이 numpy 2.x 까지 끌어올렸다.
- Why it failed: `() -> handle` TypeError 는 pybind11 이 TF 의 올드 스타일 바인딩을
  numpy 2.x 타입 체계와 연결하지 못하는 시그니처다 — protobuf 를 먼저 의심해
  protobuf 만 내리면 소용없다(실제로 3차례 왕복했다). **TF 2.10 계열에서 이
  에러를 보면 numpy 부터 본다.**
- How it was fixed: numpy 복원이 핵심. protobuf 는 3.20.3(다리 버전), onnx 는
  TF 와 numpy 요건이 교차하는 유일 낮은 지점 1.13.0. 최종 조합은
  reader_onnx_spec.md 에 고정해 뒀다.

## Case 2: 코퍼스 전량이 정수 라벨 — dot·unit 지표는 측정 자체가 불가했다

### Grounding
- Git Context: `hash:3a66bfc`
- Artifact: `assets_dev/train/audit_dot_unit_coverage.py` 출력 · 칸반 done
  「dot·unit 지표 추가」
- Confidence: 5/5 (라벨 2,512장 전수 집계)

### Discovery
mmol/L 소수점 오독(10배 오류)을 완전일치율에서 분리해 보려 했더니 측정할
표본이 없다. `labels.jsonl` 2,512장 **전부 정수**(값 30~511, 자릿수 2~3),
소수점 표본 0건, 단위(unit) 필드 0건. 리더 charset 도 0~9 전용(NUM_CLASSES=11,
blank 포함)이라 소수점 클래스 자체가 없다.

### Analysis
- Why non-obvious: "완전일치 97%인데 소수점은?" 이라는 질문은 측정 가능성을
  전제하는데, 그 전제가 성립하지 않았다. 지표를 먼저 설계하지 말고 **측정할
  표본의 존재부터 센다.**
- Impact: mmol/L 판독은 측정도 학습도 현재 불가 — 앱의 규칙 엔진(소수점 채널
  직접 검출)만이 유일 경로. 데이터 확보가 모든 것의 선행 과제(칸반 handoff
  「mmol/L 실츬 데이터 확보」).
- Action taken: 카드를 "지표 추가"가 아니라 "측정 불가 종결"로 닫고 데이터
  확보 판정을 사람에게 넘겼다.

## Case 3: CTC 리더 ONNX 파리티 — 디코드 1122/1122 완전일치

### Grounding
- Git Context: `hash:ca4a49c`
- Artifact: `_diag/reader_onnx_parity.json` · `assets_dev/train/export_reader_onnx.py` ·
  `assets_dev/train/reader_onnx_spec.md`
- Confidence: 5/5

### Hypothesis
tflite 가 막힌 CTC 리더(BiLSTM, G28)가 ONNX(opset 13) 에서 TF 와 같은 판독을
내는가.

### Results
캐시 홀드아웃 1,122장 전량: greedy 디코드 **100% 완전일치**, logits 최대 절대차
0.006(float32 수준), 모델 2.4MB. 캐시 배열을 양쪽에 동일 투입해 전처리 동일성은
구조적으로 보장(§36). 중간 수정 1건: 입력 채널 축 누락(3 rank → 4 rank)은
모델이 아니라 호출측 인자 문제였다.

### Analysis
- Confirmed/Refuted: 확인 — 온디바이스 전환의 모델 측 준비는 끝났다.
- Key metrics: decode 100% · max|Δlogit|=0.006 · 2.4MB.
- Implications: 남은 것은 런타임 패키지 선택과 실기기 벤치마크(사람 판정 대기).
  파리티 검증 패턴(캐시 배열 재투입)은 tflite 때 작성해 둔 규약의 재사용이다.
