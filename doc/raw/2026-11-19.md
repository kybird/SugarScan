# 2026-11-19

## Case 1: ONNX 엔진이 무시하던 카메라 ROI 를 리더 입력으로 연결

### Grounding
- Git Context: `hash:e9ce03e8a0ca0c34e0d719837f58ca7bf6e2c393`
- Evidence: `lib/ocr/src/engines/bandnet_crnn/bandnet_crnn_engine.dart`, `test/ocr/bandnet_crnn_engine_test.dart`
- Confidence: 5/5

### Error
SPEC §1.1 은 카메라 가이드 영역을 리더에 직접 주도록 정했지만,
BandNetCrnnEngine 은 frame.roi 를 읽지 않고 전체 프레임에서 검출했다.
카메라 변환기와 스캐너는 ROI 를 보존하므로 엔진 분기가 빠진 것이 원인이다.

### Design Decision
2026-11-19 사용자가 앱 코드 정합화를 직접 요청했다. 명시적 ROI 를
픽셀 경계로 반올림해 잘라 기존 리더 전처리에 전달한다. PNG 수동 정렬도
동일 계약이다. ROI 없는 사진은 기존 검출·게이트를 유지한다.
잘못된 ROI 는 미인식이며 전체 프레임 검출로 우회하지 않는다.
모델 준비 조건·폴백, 검증·합의·사용자 확인은 유지한다.

### Results
- `flutter test test/ocr/bandnet_crnn_engine_test.dart`: 통과.
- `flutter analyze`: 무경고.
- `flutter test --reporter compact`: 전체 통과.
- 비균일 원본 화소로 ROI 위치·행 복사·증거 크롭을 확인하고,
  리더 입력 정규화·리사이즈, 검출기 미호출, 잘못된 ROI 거절을 검증했다.
- 실모델 판독률·실기기 정렬·지연 개선은 측정하지 않았다.

### Analysis
GEN10D 입력 업스케일 원인 주장은 별도 측정이 필요하다. 본 수정은 그 가설을
검증하거나 모델 성능을 개선했다고 주장하지 않는다. 재검증 지시서는
`docs/reports/gen10d-input-audit-prompt.md`, 미실행 작업은 GLM_TASKS §4 에 남겼다.
