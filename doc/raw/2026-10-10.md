## Case 1: [discovery] GEN3 from-scratch — 세그축을 주재료로 쓰면 리더가 약화된다

### Grounding
- Git Context: `hash:ec04335+작업중`
- Evidence: `_diag/gen3_overnight.log`, `_diag/e2e_bandnet/gen3_16k_stack.jsonl`, `_diag/e2e_bandnet/gen3_v1_16k.jsonl`
- Confidence: 5/5

### Discovery
GEN3(세그축 6종 포함 30,000장)로 검출기·리더를 from-scratch로 학습했다:
- **검출기 gen3_v1**: 검출 실패 0(커버<0.9 기준 8장 — GEN2의 11장보다 개선)
- **리더 gen3r_v1**: **오독 130장(94.8%)** — GEN2 from-scratch(45장)보다 3배 악화
- 같은 검출기로 리더만 바꿔서 비교: rftk5 42장 vs gen3r 130장 → **리더만 바꿨는데 +88장**

오독 130장 중 89%(33/37 중간 자리)가 "오프 세그가 보여서" 생긴 오독 — 세그축을
가르쳤더니 정상 세그 구분 능력까지 흐려진 것이다.

### Analysis
- Why non-obvious: 세그축이 실촬 오류의 83%를 커버하도록 설계됐으므로 "축을 넣으면
  좋아진다"가 직관이다. 그러나 from-scratch에서 축이 주재료가 되면 모델이
  "변형된 숫자"를 정상으로 배우는 역효과가 났다.
- Impact: 세그축은 실촉 파인튜닝의 **리플레이 소량 혼합**으로만 써야 한다.
  from-scratch에 넣으면 리더가 약화된다.
- Action taken: GEN3 from-scratch 경로 폐기. 배포 후보는 ftk5_g0.06 × rftk5_foldall
  (오독 29, 98.8%)로 유지.

## Case 2: [discovery] 깨끗한 이미지도 오독 — CRNN+CTC 구조 한계의 직접 증거

### Grounding
- Git Context: `hash:ec04335+작업중`
- Evidence: 오독 29장 크롭 품질 측정 (대비·선명도가 정답 평균과 동일 이상)
- Confidence: 4/5

### Discovery
rftk5_foldall(최고 리더)의 오독 29장 중 대부분이 "깨끗한" 이미지에서 발생한다:
- 대비(잉크폭) 중앙값 ~130 vs 정답 평균 ~119 — 오독이 오히려 더 선명
- #1244(대비 160, 선명도 308), #1868(대비 196, 선명도 462) 등 정답보다 훨씬 깨끗

사람이 읽을 수 있는 이미지에서 CRNN이 틀린다 → 데이터가 아니라 모델이 정보를
추출해서 쓰지 못하는 것이다.

### Analysis
- Why non-obvious: 오독 원인을 "저대비·그림자·반사"에서 찾는 게 이 프로젝트의
  지속된 가설이었다. 그러나 측정해 보니 오독은 깨끗한 이미지에서도 똑같이 발생한다.
- Impact: CRNN+CTC의 CTC 프레임 독립 가정이 근본 한계. 데이터 증강으로는
  해결 불가능한 구조 문제.
- Action taken: A안(Transformer 디코더 + 동일 CNN) 제안. 다른 세션에서 진행.

## Case 3: [error] str.replace 다중 치환 사고 — 같은 패턴이 다른 함수까지 덮음

### Grounding
- Git Context: `hash:ec04335+작업중`
- Evidence: synth_lcd.py add_local_shadow 오염(2026-10-09), add_band_reflection 오염(2026-10-10)
- Confidence: 5/5

### Error
str.replace로 특정 함수의 블록을 교체하려 했으나 같은 패턴이 다른 함수에도 존재해서
의도치 않은 함수까지 덮어씀. 하루에 두 번 발생.

### Fix Code
블록 통째 교체: 여러 줄의 고유한 문맥을 포함한 anchor로 정확히 하나만 매치시킨다.
assert s.count(anchor) == 1 가드 필수.

### Analysis
- Root cause: python의 str.replace는 기본적으로 ALL occurrences를 바꾼다.
- Why it failed: 단일 라인 패턴이 여러 함수에 공통으로 존재하는 것을 확인하지 않음.

- Patterns:
- **Anti-Patterns**: str.replace로 다중 라인 블록 교체 시 count 가드 없이 사용
