## Case 1: [discovery] GEN3 from-scratch — 세그축을 주재료로 쓰면 리더가 약화된다

### Grounding
- Git Context: `hash:ec04335+작업중`
- Evidence: `_diag/gen3_overnight.log`, `_diag/e2e_bandnet/gen3_16k_stack.jsonl`, `_diag/e2e_bandnet/gen3_v1_16k.jsonl`
- Confidence: 5/5

### Discovery
GEN3(세그축 6종 포함 30,000장)로 검출기·리더를 from-scratch로 학습했다:
- **검출기 gen3_v1**: 검출 실패 0(커버<0.9 기준 8장 — GEN2의 11장보다 개선)
- **리더 gen3r_v1**: **오독 130장(94.8%)** — GEN2 from-scratch(45장)보다 3배 악화
- 같은 검출기로 리더만 바꿔서 비교: rftk5 42장 vs gen3r 130장 → **리더만 바꿨는데 +88장**

오독 130장 중 89%(33/37 중간 자리)가 "오프 세그가 보여서" 생긴 오독 — 세그축을
가르쳤더니 정상 세그 구분 능력까지 흐려진 것이다.

### Analysis
- Why non-obvious: 세그축이 실촬 오류의 83%를 커버하도록 설계됐으므로 "축을 넣으면
  좋아진다"가 직관이다. 그러나 from-scratch에서 축이 주재료가 되면 모델이
  "변형된 숫자"를 정상으로 배우는 역효과가 났다.
- Impact: 세그축은 실촉 파인튜닝의 **리플레이 소량 혼합**으로만 써야 한다.
  from-scratch에 넣으면 리더가 약화된다.
- Action taken: GEN3 from-scratch 경로 폐기. 배포 후보는 ftk5_g0.06 × rftk5_foldall
  (오독 29, 98.8%)로 유지.

## Case 2: [discovery] 깨끗한 이미지도 오독 — CRNN+CTC 구조 한계의 직접 증거

### Grounding
- Git Context: `hash:ec04335+작업중`
- Evidence: 오독 29장 크롭 품질 측정 (대비·선명도가 정답 평균과 동일 이상)
- Confidence: 4/5

### Discovery
rftk5_foldall(최고 리더)의 오독 29장 중 대부분이 "깨끗한" 이미지에서 발생한다:
- 대비(잉크폭) 중앙값 ~130 vs 정답 평균 ~119 — 오독이 오히려 더 선명
- #1244(대비 160, 선명도 308), #1868(대비 196, 선명도 462) 등 정답보다 훨씬 깨끗

사람이 읽을 수 있는 이미지에서 CRNN이 틀린다 → 데이터가 아니라 모델이 정보를
추출해서 쓰지 못하는 것이다.

### Analysis
- Why non-obvious: 오독 원인을 "저대비·그림자·반사"에서 찾는 게 이 프로젝트의
  지속된 가설이었다. 그러나 측정해 보니 오독은 깨끗한 이미지에서도 똑같이 발생한다.
- Impact: CRNN+CTC의 CTC 프레임 독립 가정이 근본 한계. 데이터 증강으로는
  해결 불가능한 구조 문제.
- Action taken: A안(Transformer 디코더 + 동일 CNN) 제안. 다른 세션에서 진행.

## Case 3: [error] str.replace 다중 치환 사고 — 같은 패턴이 다른 함수까지 덮음

### Grounding
- Git Context: `hash:ec04335+작업중`
- Evidence: synth_lcd.py add_local_shadow 오염(2026-10-09), add_band_reflection 오염(2026-10-10)
- Confidence: 5/5

### Error
str.replace로 특정 함수의 블록을 교체하려 했으나 같은 패턴이 다른 함수에도 존재해서
의도치 않은 함수까지 덮어씀. 하루에 두 번 발생.

### Fix Code
블록 통째 교체: 여러 줄의 고유한 문맥을 포함한 anchor로 정확히 하나만 매치시킨다.
assert s.count(anchor) == 1 가드 필수.

### Analysis
- Root cause: python의 str.replace는 기본적으로 ALL occurrences를 바꾼다.
- Why it failed: 단일 라인 패턴이 여러 함수에 공통으로 존재하는 것을 확인하지 않음.

- Patterns:
- **Anti-Patterns**: str.replace로 다중 라인 블록 교체 시 count 가드 없이 사용

### Hypothesis
사람 질문: "datumo 가 우리 훈련에 쓰였나?? 라이센스에 명시하면 법적책임없어지나?" — 앱 반입 배포 쌍(`band_detector.onnx`=ftk5_g0.06 × `reader_crnn.onnx`=rftk5_foldall)의 데이터 계보와 배포 의무를 사실로 확정한다.

### Results
- **둘 다 쓰였다.** 검출기·리더 모두 베이스(합성 전용: gen2_v1_step8000·리더 25k) 위에 **Datumo 납품본 2,504쌍으로 실촉 파인튜닝**(2026-10-09 사람 지시 K=5, foldall). 외부 사전학습 가중치·외부 데이터셋은 베이스에 0(SPEC §5.3 준수 — 합성 코퍼스의 "COCO" 는 어노테이션 파일 형식이지 COCO 사진이 아니다. 배경은 절차적 생성).
- **계보상 따라오는 의무는 Datumo 하나.** 옛 YOLOX 계보(gmscreen_ft3, Datumo 410장·Roboflow·COCO 사전학습)는 2026-09-17 전체 폐기라 앱 반입 없음. 런타임(ONNX Runtime)은 MIT 확인 완료.
- **"라이선스에 명시하면 책임 없어지나?" → 아니오.** LICENSES.md 기재는 내부 기록·선의의 증거일 뿐 이용 권리를 만들지 않는다. 권리는 Datumo(TILDE) 와의 구매 계약에서만 나온다. CC BY 같은 "고지하면 자유" 조건과 달리 **구매 조건 문서 자체가 미수령**(§4, 2026-08-27 개봉 후 지금까지)이라 "무엇을 지키면 되는지"를 알 수 없다. 기재는 의무 이행이 아니라 위험의 자가 진단이다.

### Analysis
- Why non-obvious: "우리 합성으로만 학습"(SPEC §3·§5.3)이라는 설계 원칙이 있어 "실촵 파인튜닝"이 계보에 어떤 의무를 다시 끌어들이는지 직관적으로 안 보였다. 2026-09-19 "실사진은 검증에만"(§1.4) 규칙도 있었으나 2026-10-09 사람 지시로 배포 쌍에 한해 대체됐다 — LICENSES.md §1.4 에 예외로 기록했다.
- Implications: ① **스토어 출시는 구매 조건 문서 확정 전 차단**(내부 빌드·테스트 배포는 가능). ② 조건이 파생 가중치 배포를 금지·불명확하게 하면 **합성 전용 체크포인트로 갈아타는 우회로**가 있다(베이스 그대로: 오독 45·98.20% — 실촉판 99.4% 기대 대비 약 −1pp, `eval_e2e_bandnet.py` 로 재검증 필요). ③ 기록은 배포 자산 단위(체크포인트 쌍)로 계보를 남겨야 계보가 실제 번들과 어긋나지 않는다.
- Action taken: `docs/LICENSES.md` §1 표 배포 쌍 행·§1.4 예외 갱신·§1.6 계보 신설·§4 첫 항목을 "출시 차단 조건"으로 승격.

### Analysis
- Why non-obvious: "무료"의 기준이 셋으로 갈린다 — ①CC0(의무 0) ②CC BY/Apache(고지로 이행) ③조건 문서 자체가 없음(Datumo). 그리고 Datacluster 는 **라이선스 필드(CC0)와 설명문(전체 3,000+장 유료 판매·배타적 소유 주장)이 서로 모순** — 필드가 게시자 본인 설정이라 CC0 가 우선한다고 보는 게 합리적이나, 상업 배포 전 sales@datacluster.ai 로 확인하는 것이 이 긴장을 닫는 유일한 방법이다.
- Impact: "조건 걸린 실촬 없이 출시"하는 경로의 실촬 재료는 사실상 Datacluster 238장뿐이다. 단 ①밴드 상자·값 GT 라벨이 없어 우리가 직접 만들어야 함(기기 상자 VOC·rotation 만 있음, 화면 숫자 가독은 1장 검증됨 `183`) ②§1.4 규칙이 CC0 도 "이 규칙 아래 통일"로 학습 금지 중 — 풀려면 사람 결정 ③238장(≈datumo 의 1/10, 인도 크라우드소싱 추정)이 파인튜닝 효과(오독 45→15)를 얼마나 재현할지는 미측정.
- Action taken: LICENSES.md §1.5 Datacluster 행에 2026-10-10 재확인 갱신. 출시 우회로 검토는 사람 결정 대기.
