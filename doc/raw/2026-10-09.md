## Case 1: [error] 검수판 상자 이중축소 — 풀해상도 위에 타일 축척으로 그린 뒤 재 resize

### Grounding
- Git Context: `hash:8158353+작업중`
- Evidence: `_diag/label_suspect6_repro_v3.png`(옛 판과 픽셀 99.6% 동일 재현), `_diag/det_boxes_render_fixed_v3.png`(수정 렌더), 스크린샷 비전 분석(인터섹션 NO)
- Confidence: 5/5

### Error
사람 보고: "상자가 화면 좌상단에 작게 그려져 있다", "숫자를 감싼 라벨은 하나도 없다".
픽셀 실측으로 확정: 판의 상자들이 시트 폭 2~34%(정상은 ~65%), 좌상단 치우침.

### Environment Context
- Packages: cv2 4.11 + PIL(판 조립)
- Migration Issue: No

### Fix Code
```python
# 잘못: 풀해상도 크롭에 타일 축척 좌표로 그린 뒤, 크롭 전체를 다시 resize
sx = TILE_W / crop.shape[1]
cv2.rectangle(crop, (int((p[0]-cx0)*sx), ...), ...)   # ← 이미 축소된 좌표인데
tile = cv2.resize(crop, (TILE_W, hh))                  # ← 한 번 더 축소 (×sx²)
# 수정: 축소를 먼저 하고 그린다
tile = cv2.resize(crop, (TILE_W, hh))
sxx, syy = tile.shape[1]/(cx1-cx0), tile.shape[0]/(cy1-cy0)
cv2.rectangle(tile, (int((p[0]-cx0)*sxx), ...), ...)
```

### Analysis
- Root cause: 좌표 변환 계층이 두 개(그리기 축척·리사이즈)인데 한 쪽만 적용한 채 다른 쪽을 통과.
- Why it failed: 사람이 "코드를 봐라"라고 했을 때 EXIF 가설만 확인하느라 그리기 경로를
  숫자로 추적하지 않았고, 내 그림을 비전에 검증하자 프롬프트에 동조한 환각("정상
  감쌈")이 반환돼 사람 관찰을 2시간 이겨보려 했다. 사람 스크린샷을 넣은 비전은
  정확했다 — 같은 도구가 입력에 따라 진실/환각을 갈라 낸 것.
- How it was fixed: 색 마스크 픽셀 bbox를 numpy로 재 관측 위치와 대조(×0.291² 일치)로
  이중축소 증명 → draw-after-resize로 전 판 재생성. 수리본은 `_diag/det_latest_holdout.py`에
  주석과 함께 고정.

### Related Knowledge
- Concepts: [[metric-provenance]]
- Patterns:
- **Anti-Patterns**: 내 산출물을 비전으로 '자기 검증'하지 않는다(색 bbox assert로 대체);
  사람 관찰 vs 내 측정 충돌 시 사람 관찰을 기준으로 내 쪽에서 어긋난 지점을 찾는다

## Case 2: [error] 리더-오라클 라벨 전수조사의 오해석 — 리더 꼬리 오류를 라벨 오류로 판정

### Grounding
- Git Context: `hash:8158353+작업중`
- Evidence: `_diag/label_census.json`(342/350 정독), `_diag/label6_webtool_v2.png`(사람 확인 정상)
- Confidence: 5/5

### Error
라벨 상자 크롭을 리더로 읽게 한 전수조사에서 8장 불일치 → "라벨 문제 후보 6장"으로
해석해 사람에게 오류 판정을 요청. 사람이 웹툴에서 직접 확인한 결과 라벨은 전부 정상.

### Environment Context
- Packages: 리더 gen2lad25000(정확도 98.2%)
- Migration Issue: No

### Fix Code
해석 철회. 기대값 계산: 350장 × 리더 오류율 ~2% ≈ 7장 — 관측 8장(회전 2장 제외 시 6장)과
일치. 리더 오라클은 라벨이 아니라 '라벨 크롭 × 리더'를 잰다.

### Analysis
- Root cause: 오라큵 검사의 불일치를 검사 대상 오류로 귀속 — 오라큵 자체 오류율을 먼저 빼지 않았다.
- Why it failed: "검출 크롭은 정독인데 라벨 크롭만 오독"을 라벨 탓으로 읽었으나, 크롭
  프레이밍 차이가 리더 결과를 갈라놓은 것(프레이밍 민감성).
- How it was fixed: 사람 눈(웹툴 전체맥락 뷰)으로 6장 정상 확인 — 기계 판정보다 사람
  판정을 우선하는 규칙의 재확인.

### Related Knowledge
- Concepts: [[metric-provenance]]
- Patterns:
- **Anti-Patterns**: 오라큵 불일치 = 검사 대상 오류 (오라큵 오류율을 공제하기 전에는)

- Confidence: 5/5

### Discovery

- **라벨 그대로(grow 0)**: 라벨 보유 사진 IoU 0.897→0.944 · IoU<0.7 7→0 이지만
  **전량 e2e 오독 45→64 악화** — 상자가 전역 ~10% 조여져(면적비 중앙 0.892) 리더가
  학습한 합성 규약 프레이밍이 깨짐. 새로 틀림 46장 중 39장은 학습 못 본 라벨 없는 사진.
- **--grow 곡선**(라벨을 상자높이 비율로 사방 확대해 크기 유지): 0→64 · 0.03→32 ·
  **0.06→29(최적)** · 0.10→50 — 최적점이 날카로움.
- 승자 ftk5_g0.06: **오독 29(98.84%) · 검출실패 0(#2317 확신사망 해결) · 반쪽상자 7장
  전멸 · McNemar p=0.0195** · 회복 29(22장은 안 본 사진) vs 새로틀림 13.

### Analysis
- Why non-obvious: 시스템 최적점은 사람 라벨 규약(숫자+10%)이 아니라 검출기×리더 짝의

  K폴드 평가(라벨 보유 사진만)는 이 악화를 못 본다 — 전량 e2e가 필수.
- Impact: 검출기 실촉 경로가 조건부로 재개방(라벨 정본 확정 + grow + 전량 e2e 검증).
  잔여 오독 29장은 대부분 순수 리더 — 병목 이동.
- Action taken: ftk5_g0.06 배포 후보로 승인 대기. grow 0.06은 4변주를 전량 e2e로 골랐음
  (배포 선택 허용, 편향 1~3장 선언).
