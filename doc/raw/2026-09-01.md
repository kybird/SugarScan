## Case: CTC hold-out 기준선 정정 3.8%→5.1% — GT blank-조인 아티팩트가 비교를 12건 오류 처리

- **증상/계기**: CTC 다음 레버(렌더러 실화면화 vs 실데이터 확충 vs 모델 확대 vs 시간 줄 마스킹) 방향 결정용 근거 분석 중 `reader_preds.json`의 GT 문자열이 blank(클래스 10) 조인 아티팩트로 오염돼 있음을 확인. 저장본 그대로 비교한 exact = 34/903(3.8%), `labels.jsonl`의 `reading` 필드를 진짜 GT로 비교하면 **46/903(5.1%)**. 반전 예시(verbatim): `{"glucose_batch1/862": ["90", "9010"]}`, `{"glucose_batch1/1209": ["88", "8810"]}`, `{"glucose_batch1/473": ["91", "9110"]}` — 뒤의 "XX10"가 진짜 값. 예측 쪽은 greedy_decode가 blank를 건너뛰어 깨끗함(4자리 이상 예측 0.1%).
- **상태**: `ctc_reader_v2.py`의 `gt_strs` blank 필터 수정은 이미 코드에 반영돼 있음 → 다음 ft 실행부터는 자동으로 올바른 수치. 학습셋 "6.8%"도 같은 이유로 소폭 저평가였던 것.
- **같은 세션 추가 발견(방향결정 근거)**:
  1. **시간 줄 간섭 가설 약화** — 오류 857건 중 예측이 화면 시각(HHMM) 부분문자열인 건 23건(2.7%), hour 대역별 정확도 균일, 4자리 이상 예측 1건(0.1%). 모델은 이미 길이(2~3자리)를 맞춰 내고 있음 → 마스킹 레버의 기대값 낮음.
  2. **'1'/'0' 쏠림의 실체 = 후미 자리 판별 붕괴** — 위치별 글자 정확도 1·2·3번째 = 80.3% / 37.4% / 17.8%. 0/1만으로 구성된 예측 306/903(33.9%, GT는 45/903), '1' 포함 예측 91.8%. 최빈 오답 '11'(107)·'101'(77)·'100'(71)·'121'(71). 혼동 top: GT 2→1(64)·8→0(53)·7→1(51)·9→1(48)·3→1(48)·6→0(44).
  3. **워프 종횡비 왜곡(구조적 도메인 갭)** — `build_cache_v2.py` `build_real()`이 GM 박스(YOLOX 축정렬 박스)를 무조건 320×160(2:1)으로 스트레치. `gmscreen_quads.jsonl` 2,007장 종횡비 중앙값 0.83(세로형 화면) → 실사진 rect는 숫자가 세로로 ~2.4배 눌린 납작 글리프. 합성 렌더러(`synth_lcd.py`)는 자연 비율(dw=0.58×dh)로 그림 → 학습·평가 모두 왜곡된 채. `diag_holdout_sheet.png`·`diag_train_sheet.png` 눈검증과 일치(납작 숫자·날짜/시간 숫자 줄이 빽빽한 실제 화면).
  4. **쓰레기 rect 존재** — holdout 903장 중 평균 밝기<60(검은 프레임류) 8.0%·표준편차<20(질감·무패턴) 5.5%, 60표본 눈셈으로는 ~13%(가죽 질감·S버튼 뒷면·스트립 포트 등). 학습 라벨 노이즈 + 정확도 상한(~90%) 양쪽에 걸림.
  5. **±90/180·와이드는 이번 셋에 없음** — 쿼드 상변 세로 0/2,007, wide(>3.0) 0.1% → 해당 렌더러 변주의 현재 기여치 낮음.
