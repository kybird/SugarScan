
## Case N: 검수 화면이 통째로 깨진 이유가 셋이었다 — 하나씩 벗겨야 보였다

### Grounding
- Git Context: `hash:2851cb1` 직후
- Evidence: 브라우저 콘솔 404 60건 · `/api/bandreal` 응답 · 추출 디렉터리 목록
- Confidence: 5/5

### Error

사람 보고:

> ?? 웹툴에서  bandreal 들어가면 모든사진이깨져있는데

### Analysis

**코드를 보기 전에 현장을 조회했다.** `/photo` 를 직접 쳐서 60,257바이트짜리
정상 JPEG 이 나오는 것을 먼저 확인했다 — 서버는 멀쩡했다. 그래서 화면으로
내려가 콘솔을 읽었고, 404 60건이 전부 `id=rf%2F...` 였다.

원인이 **셋이 겹쳐** 있었고, 하나를 고칠 때마다 다음 것이 드러났다.

1. **`ALT_CORPORA` 에 `rf` 가 없었다.** Roboflow 평가기를 새로 붙이면서
   `/photo` 의 경로 해석에는 안 붙였다. 평가기에 코퍼스를 추가하면 여기도
   같이 추가해야 한다.
2. **기본 선택이 이름 순 마지막이었다.** 그래서 `roboflow_*` 가 첫 화면에
   떴다. "정답이 있는 것"으로 거르려 했지만 로보플로도 READING 라벨이 있어
   안 걸러졌다. 코퍼스 앞머리로 가르고, **가장 최근에 평가한 것**을 고르게
   했다(`mtime`).
3. **`_diag/band_real/` 에 평가 결과가 아닌 파일이 산다.** `diag_band_cells`
   의 `cells_*.jsonl` 이 같은 폴더에 쌓이는데 API 가 `*.jsonl` 을 전부
   읽어서, 진단 파일을 모델로 골라 "검출 실패 272" 를 띄웠다. 이름으로
   거르면 새 진단이 생길 때마다 또 샌다 — **스키마로 걸렀다**(`pred`·`det`
   키 유무).

그리고 3번을 고친 뒤 남은 4장은 별개였다: **파일이 `.jpeg` 인데 `/photo` 가
`.jpg` 만 붙였다**(1,273장 중 123장). 평가기는 COCO 의 실제 파일명을 썼으므로
**수치는 멀쩡했고 화면 조회만** 깨졌다. 확장자를 하나로 가정하지 않게 고쳤다.

### Fix Code

```python
# webtool.py — 확장자를 하나로 가정하지 않는다
for _ext in (".jpg", ".jpeg", ".png", ".JPG", ".JPEG"):
    cand = ALT_CORPORA[pre] / f"{rest}{_ext}"
    if cand.exists():
        src = cand
        break
```

## Case 2: 전체 사진 검출기의 합성 전경은 아직 GM 크롭이었다

### Grounding
- Git Context: `hash:346aaa2`
- Evidence: `assets_dev/train/synth_panel.py`의 "몸체 + 액정 — GM 크롭과 같은 물건" 블록, `synth_coco/TB/train2017`, `_diag/audit/synth_preview.jpg`, `_diag/audit/datumo_failures.jpg`, `_diag/audit/rf_preview.jpg`
- Artifact: `docs/reports/band-recovery-audit-2026-09-19.md`
- Confidence: 5/5 (렌더 범위와 코드); 실패의 인과 크기는 아직 미확정

### Discovery

인수인계의 '기기 몸체'는 전체 혈당계 형상을 구현했다는 뜻으로 읽혔다. 실제
학습 샘플을 보고 코드로 돌아가니 LCD 주변 크롭의 테두리를 만들고 있었다.
그것을 축소하고 배경을 바꿔도 버튼부를 가진 전체 기기가 되지 않는다.
실촬 실패에는 버튼·로고·배터리 표시로 이동한 예측과 숫자 일부 잘림이 공존한다.
여백 확대 하나로 둘을 같이 고칠 수 있다는 근거는 없다.

### Analysis

- 기존 `measure_panel_stats.py`에 입력 레터박스 기준 짧은 변 층화를 추가했다.
  해상도 탐침은 정답 크롭 없이 같은 사진과 같은 가중치로 비교한다. 측정 명령과
  결과는 감사 문서에 남긴다. 실촬 한 코퍼스의 개선만 보고 해상도를 채택하지 않는다.
- 미사용 `--aug`에서 이미지 인덱스에 고정된 변환, 캔버스가 표적을 자르지만
  라벨은 남기는 경로, 정수 resize와 좌표 스케일 불일치를 확인하고 수정했다.
  이 경로는 기존 bg 모델 학습에 사용되지 않았으므로 기존 실패 원인으로 소급하지 않는다.
- 그림과 라벨 정렬, 전체 표적 가시성, 방문별 변화와 재현성을 실제 Dataset
  경로에서 테스트한다. `python -m unittest test_band_augmentation test_band_input_scale -v`.
- 학습 사진을 추가하거나 외부 가중치를 들이지 않았다. 평가용 실촬을 반복해서
  모델 선택에 쓰므로 최종 독립 평가라는 주장도 하지 않는다.
