> 상태: subagent 리뷰 대기

## 1. 배경

### 1.1 문제 요약
CTC 리더(사진 → LCD 화면 → 숫자열)의 hold-out 완전일치가
v1(6에폭) 0%, v2(40+20에폭, 3k 합성) 7.9%에 머무름.
v3(12+12에폭, 23k 합성 + 개선 렌더러)은 22.2%로 3배 향상했으나
학습에 16시간 소요 — 데이터 파이프라인 병목 때문.

### 1.2 15시간 병목의 원인 (확정)

| 병목 | 위치 | 원인 |
|---|---|---|
| **데이터 로딩** (주범) | cv2.imread 12MP JPEG → 320×160 resize, 매 스텝 단일 스레드 | GPU가 데이터 대기 |
| BiLSTM 순차 연산 | 40 타임스텝 × batch 16 | GPU 병렬화 한계 |
| steps_per_epoch 미지정 | while True 무한 제너레이터 | Keras가 에폭 끝 판단 불가 → 영원히 에폭 1 |
| 체크포인트 부재 | 중단 시 전체 손실 | ModelCheckpoint 미구현 |

### 1.3 데이터 자체는 유효 (전수 감사 완료)
- 합성 23,000장: 렌더러 v2 (광택·비네팅·회전·폭 지터) — 2026-08-30 확인
- 실사진 rect 240장: GM 박스 → 화면 펴기 — 전수 감사에서 대다수 양호
- hold-out: 미라벨 1,767장 (GM 검출 성공분)
- 불량 소수(~15%): 과노출·암부·기기 잘림 — 실사진의 현실적 품질 편차

## 2. 개선 설계

### 2.1 [P0] 데이터 캐시 — .npz 구축

```
목적: 디스크 I/O 제거 → GPU-bound 학습
방법: 전체 이미지를 한 번 디코딩 → numpy 배열 → .npz 저장
파일: assets_dev/train/data_cache.npz
  synth_images: (23000, 160, 320) uint8 — 1.2GB
  synth_labels: (23000,) 문자열
  real_images: (240, 160, 320) uint8
  real_labels: (240,) 문자열
  real_ids: (240,) id 목록
구축 소요: 23k 디코딩 ≈ 30~40분 (일회성)
이후 로딩: np.load → 수 초
```

### 2.2 [P0] 학습 스크립트 개선 (ctc_reader_v2.py)

```
변경:
  1. 데이터: .npz → tf.data.Dataset.from_tensor_slices (in-memory)
  2. shuffle(10000) + batch(32) + prefetch(AUTOTUNE) — GPU 항상 공급
  3. steps_per_epoch 명시 → 무한 제너레이터 문제 해결
  4. ModelCheckpoint — 매 에폭 저장 (이어학습 가능)
  5. CSVLogger — 진행률 파일 기록 (버퍼링 무관)
  6. EarlyStopping — val_loss 기반
  7. 배치 크기 16 → 64 (GPU 메모리 여유 활용)
유지:
  - 모델 구조: CNN(32/64/128) → Reshape → Dense → BiLSTM(96) → Dense(11) + CTC
  - 입력: 320×160 grayscale
  - 학습 데이터: 합성 23k + 실사진 240장
```

### 2.3 [P1] 이어학습 (체크포인트 재개)

```
목적: 언제든 중단해도 마지막 체크포인트부터 이어서 학습
구현:
  1. 학습 시작 시 checkpoints/ 디렉터에서 latest 체크포인트 탐색
  2. 있으면 load_weights → initial_epoch 설정
  3. 없으면 처음부터
검증:
  - 3에폭 학습 → 강제 종료 → 재시작 → 정확히 이어지는지 확인
```

### 2.4 [P1] 진행률 가시화

```
문제: stdout 버퍼링으로 학습 상태 파악 불가
수정:
  1. python -u 또는 PYTHONUNBUFFERED=1
  2. tf.keras.callbacks.CSVLogger — 에폭마다 CSV 기록
  3. tf.keras.callbacks.ProgbarLogger — 콘솔 진행바
효과: 학습 중 실시간으로 에폭·loss·정확도 확인 가능
```

## 3. 실행 계획

| 단계 | 작업 | 소요 | 의존 |
|---|---|---|---|
| 1 | .npz 캐시 구축 (23k+240 디코딩) | 40분 | 없음 |
| 2 | 학습 스크립트 v2 작성 + 이어학습 | 15분 | 없음 |
| 3 | 학습 실행 (40 에폭, 캐시 사용) | 5~15분 | 단계 1, 2 |
| 4 | hold-out 평가 | 3분 | 단계 3 |
| 5 | 판정 → 다음 레버 결정 | 즉시 | 단계 4 |

**총 소요: 캐시 구축 40분 + 학습 5~15분 = 약 1시간 내 판정**

## 4. 성공 기준

| 기준 | 목표 | 측정 방법 |
|---|---|---|
| 학습 속도 | 에폭당 < 30초 | 캐시 사용 vs 기존 15~25분/에폭 |

| 체크포인트 이어학습 | 중단→재시작 시 정확히 이어짐 | 수동 검증 |
| GPU 활용률 | > 60% (기존 33~68%) | nvidia-smi |
