# Claude 작업 목록 (C 시리즈)

이 문서는 **위임하지 않고 직접 판단해서 해야 하는 작업**의 목록이다.
짝이 되는 문서가 [`GLM_TASKS.md`](GLM_TASKS.md) 이고, 끝난 일은
[`DONE.md`](DONE.md) 로 옮긴다.

---

## 1. 무엇을 기준으로 갈랐나

작업의 크기가 아니라 **틀렸을 때 무엇이 일어나는가**로 갈랐다.

| | Claude (C) | GLM (G) |
|---|---|---|
| 정답의 위치 | 아직 아무 데도 없다. 정하는 것이 작업이다 | 이 저장소 문서 어딘가에 이미 적혀 있다 |
| 틀렸을 때 | 값이 조용히 어긋나거나, 되돌릴 수 없거나, 법적으로 걸린다 | 화면이 어색해지고 리뷰에서 잡힌다 |
| 검증 | 사람이 읽어야 안다 | `flutter analyze` + `flutter test` 로 끝난다 |
| 범위 | 여러 파일에 걸친 결정 | 파일 몇 개, 지시문에 다 적혀 있다 |

**"작아 보이는데 C 에 있는 것"들이 있다.** 소수점 표기(C5)는 문자 한 개 문제이고
`dart format`(C7)은 명령 한 줄이다. 둘 다 판단이 필요해서 여기 있는 것이지 분량
때문이 아니다. 반대로 4개 언어 번역(G8)은 분량이 컸지만 판정 기준이 문서에
적혀 있어서 위임할 수 있었다.

**GLM 에게 넘기기 전에 C 가 먼저 끝나야 하는 것들이 있다.** §4 에 모아 두었다.

## 2. 작업 목록

### C1 — 동의와 개인정보처리방침 ★ 출시 차단

**상태**: 미착수 · **우선순위 1** · 근거: [IMPLEMENTATION_PLAN.md §15 "출시 전 필수"](IMPLEMENTATION_PLAN.md)

지금 앱은 **로그인하면 아무것도 묻지 않고 혈당 기록을 싱가포르 서버로 보낸다.**
기능이 빠진 게 아니라 스토어 등록 자체가 막히는 구멍이다.

왜 위임하지 않나
- **동의 항목을 잘못 나누면 동의가 무효가 된다.** 민감정보 처리 동의와 국외
  이전 동의는 **각각** 받아야 하고, 하나로 묶는 순간 둘 다 효력을 잃는다.
  이건 UI 취향이 아니라 PIPA 제28조의8 의 요건이다.
- 고지 항목(이전받는 자 = Supabase, 국가 = 싱가포르, 목적, 보유·이용 기간)이
  바뀌면 다시 고지하고 다시 동의를 받아야 한다. 문구와 데이터 구조가 함께 간다.

할 일
1. 로그인 전 동의 화면. 두 동의를 **분리된 체크박스**로. 고지 4항목을 화면에 적는다.
2. 동의 사실을 로컬에 남긴다(버전·시각). 문구가 개정되면 재동의를 받아야 하므로
   **동의 문구 버전**을 함께 저장한다. 이걸 안 남기면 개정 시 누가 무엇에 동의했는지
   증명할 수 없다.
3. 개인정보처리방침 문서 + 공개 URL(Play 등록 필수).
4. Play Console Data safety 양식 — 건강 데이터 수집·전송 신고.
5. 동의 철회 경로. 철회하면 push 를 멈춘다(로컬 기록은 남긴다 — "기록을 남기지
   못하는 상태를 만들지 않는다" 규칙).
6. 배포 국가 결정. EEA 를 포함하면 SCC 문서가 붙는다.

주의
- 동의 화면이 **로그인 게이트보다 앞**에 서야 한다. 순서가 뒤집히면 동의 전에
  세션이 생긴다.
- 서버 미설정 빌드(`RemoteDisabled`)에서는 동의 화면을 띄우지 않는다. 국외로
  나가는 데이터가 없는데 동의를 받으면 그게 더 이상한 고지다.
- 6개 언어 전부에 문구가 필요하다. **법적 문구의 번역은 G 로 내려보내지 않는다**
  (G8 의 역번역 검증은 서술 문구용 절차였다).

완료 기준: 동의 없이는 서버로 아무것도 나가지 않는다. 동의 상태와 버전이
저장된다. 방침 URL 이 존재한다. 테스트로 고정한다.

> 법률 자문이 아니다. 출시 전에 확인받을 것 — 특히 동의 문구와 항목 분리.

### C2 — OCR 실기기 튜닝과 W7 승격 게이트 ★ 제품 리스크 1위

**상태**: 미착수 · 근거: [IMPLEMENTATION_PLAN.md §2.6~2.7, §13 R-1](IMPLEMENTATION_PLAN.md)

`SegmentRuleEngine` 은 단위 테스트로만 검증됐다. **실제 혈당계를 실제 조명에서
읽어 본 적이 없다.** 이 프로젝트의 존재 이유가 여기에 걸려 있다.

왜 위임하지 않나
- 값을 **틀리게 읽는 방향**의 버그가 나오는 유일한 영역이다. 화면이 깨지는 것과
  137 을 187 로 읽는 것은 위험의 종류가 다르다.
- 임계값 하나를 움직이면 어떤 혈당계는 좋아지고 어떤 혈당계는 나빠진다.
  골든셋 없이 "이 기기에서 잘 되네"로 튜닝하면 다른 기기가 조용히 망가진다.
- 가이드 박스와 ROI 정렬은 **눈으로 맞추는** 일이다.

할 일
1. 실촬 데이터 수집(조명·각도·기기 조합). W1 잔여 과제이기도 하다.
2. `tools/ocr_bench` 하네스 — 골든셋에 대해 정확도를 숫자로 뽑는다.
   **기기별로 분해**해서 본다(R-2).
3. 가이드 박스 ↔ ROI 정렬을 실기기에서 확인. 인식이 전혀 안 되면 알고리즘보다
   이 정렬을 먼저 의심할 것.
4. §2.7 승격 게이트 판정. 미달이면 플랜 B(소형 CNN) 전환 결정.

주의
- **참고 저장소 코드를 붙여 넣지 말 것.** 공개 구현 상당수가 GPL-3.0/AGPL-3.0 이고,
  자체 구현이라는 사실 자체가 이 프로젝트의 라이선스 방어선이다.
- 골든셋 이미지는 저장소에 넣지 않는다(`.gitignore` 의 `assets_dev/`).

완료 기준: 골든셋에 대한 기기별 정확도 표가 있고, 게이트 통과/미달 판정이 있다.

### C3 — 주기 실행 + attempts 기반 지수 백오프

**상태**: 미착수 · 근거: [IMPLEMENTATION_PLAN.md §15 "W10 잔여 과제"](IMPLEMENTATION_PLAN.md)

지금 백오프는 "다음 촉발까지 기다림"이다. 실패 간격이 attempts 에 따라 벌어지지
않는다. 주기 실행(WorkManager / BGTaskScheduler)이 붙어야 의미가 생기는 값이라
둘을 함께 다뤄야 한다.

왜 위임하지 않나
- `test/data/sync_engine_test.dart` 가 고정한 판단들과 **정면으로 얽힌다.**
  특히 "오프라인은 실패가 아니다" — 백오프를 attempts 로 돌리면서 오프라인을
  실패로 세는 순간, 지하철을 여섯 번 타는 것만으로 아웃박스가 영구히 막힌다.
- 한도에 닿은 항목의 행은 남기고, 되살리기는 **사용자가 버튼을 누를 때만**
  (`retryBlocked()`). 자동 해제를 슬쩍 넣으면 한도가 무의미해진다.
- 백그라운드 실행은 OS 가 마음대로 죽인다. 트랜잭션 경계를 잘못 잡으면 아웃박스와
  로컬 DB 가 갈라진다.

할 일
1. attempts 기반 백오프(상한 있는 지수). 오프라인은 attempts 를 태우지 않는다.
2. WorkManager(Android) 주기 실행. iOS 는 Phase 4 로 미뤄도 된다.
3. 배터리·데이터 절약 모드에서의 동작 결정.

완료 기준: 실패 간격이 벌어지고, 오프라인 반복이 한도를 태우지 않는다는 것을
테스트가 고정한다.

### C4 — 동기화 미검증 시나리오 4개

**상태**: 미착수 · 근거: [IMPLEMENTATION_PLAN.md §15 "W10 잔여 과제"](IMPLEMENTATION_PLAN.md)

실기기에서 확인된 것은 단일 기기 push 와 다건 pull 뿐이다. 남은 것:

| 시나리오 | 무엇이 깨질 수 있나 |
|---|---|
| 다기기 pull | `pending` 스킵 규칙이 실제로 로컬 변경을 지키는지 |
| 충돌 | 같은 기록을 두 기기에서 고쳤을 때 |
| 오프라인 후 복귀 | 쌓인 아웃박스가 순서대로 나가는지 |
| 시도 한도 도달 | 행이 남는지, `retryBlocked()` 로 살아나는지 |
| `update` 경로 push | W12 잔여 — 수정이 서버에 반영되는지 |

왜 위임하지 않나: 각 시나리오의 **기대값 자체가 판단**이다. "충돌 시 어느 쪽이
이기는가"를 지시문에 적어 줄 수 없으면 위임할 것이 없다.

완료 기준: 다섯 줄이 전부 검증됨으로 바뀌고 §15 에 결과가 적힌다.

### C5 — 소수점 표기의 로케일 대응

**상태**: 미착수 · 근거: [GLM_TASKS.md §5](GLM_TASKS.md)

`GlucoseUnit.format()` 이 `toStringAsFixed` 를 써서 **항상 점을 찍는다.**
독일어·프랑스어·스페인어권은 쉼표를 쓴다. 스위스 사용자가 `7,6` 을 입력하고
`7.6` 을 보게 된다.

왜 위임하지 않나
- **단위 표기는 이 앱에서 가장 위험한 자리다.** 10~50 정수는 두 단위 모두에서
  유효하고 의미가 정확히 반대다. 표기를 건드리는 변경은 전부 여기를 지난다.
- `intl` 의 `NumberFormat` 을 표시 계층에 넣는 일인데, 저장·비교·직렬화 경로로
  새어 들어가면 `7,6` 이 저장되거나 파싱이 갈린다. **경계를 긋는 것이 작업의 본질**
  이고 그 경계는 지시문으로 적기 어렵다.

이미 안전한 것: 입력은 괜찮다. 검증기가 쉼표를 점으로 바꾼다.

완료 기준: 표시만 로케일을 따르고, 저장·비교·동기화 경로에는 `NumberFormat` 이
한 번도 나타나지 않는다. 테스트로 고정.

### C6 — 계정 탈퇴와 hard delete

**상태**: 미착수 · 근거: [IMPLEMENTATION_PLAN.md §15 "W9 잔여 과제"](IMPLEMENTATION_PLAN.md)

C1 과 한 몸이다. 동의를 받는 앱은 철회와 탈퇴 경로가 있어야 한다.

왜 위임하지 않나: **되돌릴 수 없는 삭제**다. Edge Function 의 권한 범위를 잘못
잡으면 남의 행을 지운다. RLS 를 우회하는 코드라 리뷰가 곧 안전장치다.

할 일: 탈퇴 시 서버 행 hard delete Edge Function, 로컬 DB 초기화, 세션 폐기,
그리고 "탈퇴하면 무엇이 사라지는가"를 사전에 보여 주는 화면.

### C7 — `dart format` 전면 적용 여부 결정

**상태**: 결정 대기 · 근거: [GLM_TASKS.md §5](GLM_TASKS.md)

Dart 3.12 의 새 포매터가 **74개 파일**을 다시 쓴다. 기능 변화는 없지만 `git blame`
이 통째로 밀린다.

**작업이 아니라 결정이다.** 할지, 한다면 언제 할지(다른 브랜치가 없는 시점),
`.git-blame-ignore-revs` 를 둘지. 정하고 나면 실행 자체는 G 로 내려보낼 수 있다
(§4 참조).

### C8 — EasyOCR 가중치 라이선스 확정

**상태**: 확인 실패로 잔여 · 근거: [LICENSES.md §4](LICENSES.md), [reports/G5-license-audit.md](reports/G5-license-audit.md)

코드는 Apache-2.0 으로 확인됐지만 **학습 가중치의 배포 조건은 공개 자료 어디에도
없다.** G5 가 조사해서 "확인 실패"로 남긴 항목이다 — 더 파도 안 나온다는 뜻이므로
Jaided AI 에 직접 문의하는 것 말고는 방법이 없다.

왜 위임하지 않나: 외부 주체와의 문의이고, 답을 받아 **모델을 반입할지 말지 정하는
것**이 본체다. 상용 배포가 걸린다. 지금은 모델 파일이 없어 당장 막히지는 않지만
C2 가 플랜 B 로 가면 곧바로 필요해진다.

### C9 — Health Connect 연동과 Play 헬스데이터 선언

**상태**: 미착수 · 근거: [IMPLEMENTATION_PLAN.md §12 W13, §13 R-4](IMPLEMENTATION_PLAN.md)

왜 위임하지 않나: 심사 리드타임이 있어 **제출 시점 자체가 결정**이고(미승인 시
Health Connect 없이 베타 선출시), 권한 문구가 C1 의 고지 항목과 맞물린다.
민감 권한을 다루는 코드라 잘못 선언하면 앱 등록이 반려된다.

## 3. 순서

```
C1 ──────────────► 출시 차단. 다른 무엇보다 먼저 착수한다
 └─ C6 (탈퇴·철회는 C1 의 고지 내용에 딸린다)

C2 ──────────────► 제품 리스크 1위. C1 과 병렬로 돈다(영역이 겹치지 않는다)

```

숫자 튜닝) 오가면서 둘 다 얕아진다.

## 4. C 가 끝나야 G 로 내려갈 수 있는 것

지금은 위임할 수 없지만, C 쪽에서 **정답을 문서에 적어 두는 순간** 단순 작업이
되는 것들이다. 결정이 끝나면 [`GLM_TASKS.md`](GLM_TASKS.md) §4 에 옮겨 적는다.

| 지금 | C 쪽에서 정해야 하는 것 | 정해지면 G 작업이 됨 |
|---|---|---|
| C7 `dart format` | 할지, 언제 할지, blame 처리 | 명령 실행 + 커밋 분리 |
| C1 동의 화면 | 문구와 항목 분리(한국어·영어 원문) | 나머지 4개 언어 번역 + 역번역 표 |
| C5 소수점 | 표시 계층 경계와 헬퍼 시그니처 | 호출부 치환 + 로케일별 테스트 |
| C2 OCR | 벤치 하네스의 입출력 형식 | 골든셋 라벨링 보조, 결과 표 생성 |
| C9 Health | 권한 문구와 선언 항목 | 문구 6개 언어 반영 |

## 5. 이 문서를 쓰는 법

- 착수하면 **상태**를 바꾼다. 끝나면 항목을 통째로 [`DONE.md`](DONE.md) 로 옮기고
  여기서는 지운다. 두 곳에 같은 내용을 두지 않는다.
