## Case 3: 리더 결정적 크롭 RAM 캐시로 반복 디코딩 제거

### Grounding
- Git Context: `hash:d5518ee66d16f9f1e610bf09981d64d68ed9f658`
- Evidence: `docs/reports/uniform-training-20261031.md`
- Confidence: 5/5

### Design Decision
사용자 요청으로 배치와 목표 에폭을 유지한 채 CPU 입력 경로만 캐시한다.
증강·지터 데이터의 캐시는 거부해 방문마다 달라야 하는 변형을 고정하지 않는다.
동일 입력 검증은 benchmark_reader_cache.py, 실행 변경은 continuation.json에 남긴다.
15에폭 체크포인트의 optimizer와 scheduler를 복원한다. 옛 체크포인트에는 RNG
상태가 없어 연속 실행과 같은 난수열을 보장하지 않으며 이후 파일에는 저장한다.

### Analysis
- 로딩 벤치마크는 전체 학습 속도나 인식 성능을 뜻하지 않는다.
- 기존 최고 모델을 백업하고 정확도 하한을 전달해 재개 후 악화된 best 교체를 막는다.

## Case 1: 첫 자리 1 편향 대응 균등값 합성을 별도 계보로 재학습

### Grounding
- Git Context: `hash:d5518ee66d16f9f1e610bf09981d64d68ed9f658`
- Evidence: `docs/reports/uniform-training-20261031.md`
- Confidence: 5/5

### Design Decision
사용자가 새 데이터 생성 후 학습 시작을 요청했다. 값당 균등 30~599 변경을
별도 UNIFORM_20261031 코퍼스에 반영하고, 이전 GEN3 학습 예산을 재사용한다.
검출기 16000스텝 후 step8000 예측 상자로 리더 150에폭을 from scratch 학습한다.
기존 코퍼스·체크포인트·앱 모델을 보존하고 생성 실패 시 학습을 막는다.

### Analysis
- 계획 재사용은 구분포를 남길 수 있으므로 새 시드·새 경로로 생성한다.
- 계획 모드와 시드도 바뀌므로 분포 변경만의 인과적 A/B라고 주장하지 않는다.
- 실촬은 평가 전용이다. 학습셋 정확도와 라이브 카메라 개선을 구분한다.

## Case 2: 생성의 All-NaN 경고는 진단 배경 중앙값 폴백 경로

### Grounding
- Git Context: `hash:d5518ee66d16f9f1e610bf09981d64d68ed9f658`
- Evidence: `assets_dev/train/_diag/uniform_20261031/warning_audit.json`
- Confidence: 5/5

### Discovery
경고 원문: `All-NaN slice encountered`.
`synth_panel._gpc_bg_contrast`에서 밴드 bbox를 제외한 유리 화소가 전부
NaN이면 nanmedian이 경고를 낸다. 기존 코드의 isfinite 검사 뒤 전체 이미지
중앙값 폴백이 작동한다. glyph_plane_score 진단 경로이며 이미지·라벨은 변경하지 않는다.

### Analysis
- `python assets_dev/train/audit_uniform_warning.py`로 로그 경고 구간을 재생했다.
- panel_20261031_5908에서 경고 스택·저장 이미지와 픽셀/라벨 일치를 확인했다.
- 매니페스트 glyph_plane_check는 전부 유한하다. 재생성 없이 학습을 계속한다.
- 생성기 소스를 바꾸지 않아 실행기의 소스 해시 계약을 유지한다.
