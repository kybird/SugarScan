# 모델 설계와 개선 과정 — 연대기 정본

작성 2026-11-19. 순수 합성 학습 스택(2026-09-17 재설계 이후)의 설계와
개선 과정을 한 문서로 정리한다. 세부 근거는 각 절 끝의 원문 링크에 있다.

**판정 기준 약속**: 이 문서의 성적은 전부 DC238(Datacluster CC0, 값 207장·
함정 31장, 판정 전용 — 학습에 실사진 0장)에서, **앱 실제 확정**(`stage=확정`:
검출게이트 0.25·면적 2% → 판독 → 값검증 10~600 → 확신도 0.85 전부 통과)만
센다. 2026-11-18 이전의 옛 집계("값통과" 기준)는 별도 표기.

## 2. 시스템 아키텍처

사진은 두 모델 + 4중 게이트 체인, 카메라는 가이드 ROI → 리더 직행이다.
모두 회색조·단말 추론. ROI 분기는 2026-11-19 사용자 요청으로 앱 구현을 정합화했다.

```
전체 사진(ROI 없음)
   │ letterbox 640(앱) / 416(학습·재판)
   ▼
[검출기 BandNet]  1.122M 파라미터(width 1.5) · obj 히트맵 + 박스 회귀
   │ 게이트: 점수 ≥0.25 · 밴드면적 ≥2%
   ▼
축정렬 박스 크롭 ──→ [판독기 CRNN]  2.3M 파라미터 · 입력 144×96 ·
카메라/수동 정렬 ROI ────────┘
   │                  시간축 36(W/4) · CTC · blank=10
   │ 값 검증: 숫자 + 10~600
   │ 확신도: 최약 자리 확신도 ≥0.85 (연속 3프레임 합의는 앱층)
   ▼
미확정(ScanUnconfirmed) 또는 확정 → 사용자 확인 시트(1탭) → 저장
```

설계 결정의 핵심(정본 `docs/SPEC.md`):
- 검출 대상은 **밴드**지 LCD 가 아니다(2026-09-17). 출력은 축정렬 사각형
  하나 — 쿼드 펴기·기울기 예측 안 함(2026-09-16).
- 검출기는 **사진 경로 전용**. 카메라 실시간 경로는 가이드박스가 크롭을
  주므로 리더가 직접 받는다. 두 경로를 다 받는 것은 리더다.
- **검출기는 "숫자줄이 있는가"만 묻는다.** 코드화면 판별·방향 같은 문맥
  판별은 프레임 층(유리 분류기, 미착수) 또는 값검증+사용자 확인의 몫 —
  GEN6~8 실패로 확정(§7).
- 확신도는 **최약 자리(worst-digit)** 확신도 — PaddleOCR 의 mean 방식과
  비교 측정에서 우위(§8-B).

## 3. 옛 설계와 그 폐기 (2026-09-17, 사람 결정)

첫 세대(gmscreen·gmscreen_ft·synthband_v*·scale_* 검출기 계보 + CTC 리더)는
전부 폐기했다. 이유는 성능이 아니라 **기반이 틀렸다는 것**:
- 모델이 YOLOX-Nano 가 아니었다(depthwise 미적용으로 별개 구조).
- COCO 사전학습이 462개 중 276개(60%)만 실림.
- 정답 상자가 밴드 기울기 탓에 중앙 16% 부풀어 있었음.
- 실촬 평가가 배포에 없는 오라클(사람이 그린 LCD 쿼드)로 재고 있었음.

폐기의 규칙: 옛 수치를 기준선으로 삼지 않고, 옛 체크포인트로 시작하지
않는다. **새 설계의 첫 수치가 첫 기준선이다.** 기록은 `doc/raw/2026-09-17.md`.

옛 판독 경로(7-세그먼트 규칙 엔진 + tflite 분류기)는 앱 폴백으로 존속 —
"수동 입력 경로 상시 개방"을 떠받친다.

## 4. 합성 데이터 생성기

정본 `assets_dev/train/synth_panel.py`(≈4,400줄) · 설계 `docs/SPEC.md` §9.

- **프로파일 15종**(세로형 중심 + 가로형 공유 0.5) — 레이아웃·숫자 종횡비·
  극성(반전)은 기기의 성질(사람 선언). 고스트 세그먼트(꺼진 8) 렌더 포함.
- **장면 그룹**: 한 배경·방해물·카메라 계획에서 세 변형이 파생 —
  정상(값 표시) / 기기 없음(음성) / 꺼짐(음성). 음성은 상자 없는 COCO 로.
- **방해물 계열**: 모자이크·인쇄물·7세그 — 검출기가 속은 크롭이 리더
  음성(빈 타깃) 학습 데이터가 된다(§5).
- **광학 축(GEN5)**: roll ±45° · 저대비(c<0.40)×센서 그레인 결합 · 주름
  글레어 0.15. DC238 실패 사진 관찰(GT329 '디더링 혼재'·GT374 '주름 글레어')
  에서 나왔다.
- 병렬 굽기 `--jobs 16`(16코어 활용, 4배). 시드가 정본 — 세대 전체가
  시드의 결정적 함수(부분 재개 대신 재굽기).

## 5. 학습 방법

**검출기**(`train_band.py`): BandNet, AMP, 음성 프레임은 objectness=0
(거절 학습). `--neg-ratio 0.25`(배치 128+32). 2026-11 기준 최적:
batch 128·2,250스텝·lr 8e-3·width 1.5 — 4GB VRAM, ~6분.

**판독기**(`reader_crnn.py`): 검출기 **제안 상자**로 크롭을 뽑아 학습
(정답 상자가 아니라 — 배포와 같은 상자 품질). 음성 오검출 크롭은 빈 문자열
CTC 타깃(길이 0). 100에폭, 학습셋 완전일치 100% 수렴. RAM 패딩 크롭 캐시로
에폭 17.7초→2.8초(2026-11-18, 커밋 55f58d9).

**배포 변환**: `export_deploy_onnx.py` → `assets/models/band_detector.onnx`
(640 입력) + `reader_crnn.onnx`. 실촉 2,504장 판정 완전 일치로 파리티 검증.

## 6. 재판 방법론 (DC238)

- 채점기 `eval_real_judge.py` — EXIF 지향 → 앱 확정 규칙 그대로 시뮬레이션.
- **집계 라벨 버그 수정(2026-11-18)**: 요약의 "확정"이 확신도 게이트에 막힌
  행까지 세던 버그(val 을 게이트 앞에서 대입). 수정 후 "확정"=앱 실제 확정,
  막힌 행은 확신도차단 버킷. 전 계보 같은 버그였으므로 옛 상대 비교는 유효.
- **재현성 규칙**: worst 0.80~0.90 경계 사진들이 GPU 비결정성에 흔들린다
  (한 프로브가 95/6/2 ↔ 87/7/7). 기준 컬럼(416)이 재판 기준과 일치하는
  실행만 채택한다.
- 통계 주의: n=207에서 오답 4건의 95%CI [0.7, 5.3] — "≤5% 달성"은 관측이지
  확정이 아니다.

## 7. 세대 연대기

표는 앱 실제 확정(§0 약속). GEN5 는 상세 유실로 옛 집계만 남음.

| 세대 | 축 | 정닥 확정 | 오답 확정 | 함정 확정 |
|---|---|---|---|---|
| 제품(실촉 FT) | 참조점 | 69.7% | 6.6% | 40.0% |
| GEN4(PS+거절) | 거절 학습 도입 | 27.1% | 6.4% | 3.3% |
| GEN5 | 광학축 3종 | (옛 집계 62.8%) | — | — |
| GEN6 | +코드화면 음성 30% | 12.1% | 6.3% | 6.5% |
| GEN7 | 코드 각도 제한 | 23.2% | 1.9% | 16.1% |
| GEN8 | +원경 거부 | 23.7% | 3.9% | 6.5% |
| GEN9 | **코드화면 제거**(GEN5 회귀) | 46.4% | 4.3% | 29.0% |
| GEN10 | +줌0.40(예산 고정) | 45.4% | 4.8% | 35.5% |
| GEN10C | 예산 단독 12,000장 | 56.0% | 5.3% | 61.3% |
| **GEN10B** | **12,000장 + 줌0.40** | **56.0%** | **2.9%** | 38.7% |
| **GEN10B@640** | **+ 640 추론(배포 정렬)** | **56.0%** | **1.9%** | **29.0%** |
| GEN10D | 640 네이티브 학습 | 39.1% | 1.9% | 35.5% |

세대별 이야기:
- **GEN4→GEN5**: 거절 학습이 실데이터에 이식됨(오확정 45.5→18.2%, 옛
  집계). 광학축이 정닥 +21.9pp. 단 함정 통과 회귀(30→58%) — 강인해진
  리더가 코드화면도 읽음.
- **GEN6~GEN8 — 코드화면 음성의 3연속 실패**: 코드화면을 검출기 음성으로
  넣자 함정은 잡히는데(12.9%) 정닥이 폭락(35~55%). 원인: 검출기가
  "숫자 있는 화면 = 어쩌면 거절"을 배워 실제 판독으로 번짐 + 음성 혼동
  3배(오검출 크롭 2,297개). 사용자 통찰 "제품 이후 학습에 Code 가 들어간
  것이 원인"(2026-11-18).
- **GEN9**: 코드화면 학습 제거로 정닥 복귀 + 오닥 사상 최저. 코드화면
  방어는 3층(값검증 → 유리 단위 게이트[미착수] → 사용자 확인)이 맡는다는
  아키텍처 확정. 합성 코드값은 혈당 범위 밖(601~999/1~9)+3자리 zero-pad.
- **GEN10B/C/D — 예산·확장·해상도 분해(2026-11-19)**: 정닥 +20은 전부
  **데이터 예산**(같은 15 프로파일인데도 — 양이 다양성을 산다). 줌 하한
  확장은 예산과 세트일 때 **안전** 축(오답 11→6·함정 19→12). 추론 640은
  **배포 정렬**(학습 416↔배포 640 불일치 교정, 오답 6→4). 640 네이티브
  학습은 합성 프레임(896px)이 업스케일되어 기각 — 고해상도 렌더가 전제
  축. 게이트 실패 21건 중 15건이 고해상도 추론에서 부활(0.06→0.99).

## 9. 확정된 구조 지식

1. **예산 = 리콜, 확장 = 안전, 추론 해상도 = 배포 정렬.** 세 축은 독립이다.
2. **"Code 때문"**: 검출기에 문맥(코드화면)을 가르치면 양성이 죽는다.
   검출기는 숫자줄만. 문맥은 프레임 층 분류기 또는 뒷단 게이트의 몫.
3. **방향(90°)과 코드화면 판별은 같은 해법으로 수렴** — 유리 영역 소형
   분류기(PaddleOCR cls 모듈이 산업 선례). rot90 14건 중 5건은 회전 후
   정확 판독 가능(축은 살아 있음, 선택기가 문제).
4. **worst-digit 확신도가 mean보다 안전 프론티어에서 우위.**
5. **간극의 정체는 기기 스타일 다양성**(프로파일 15 vs 실제 수십 종) —
   질감·스케일 통계·노이즈는 이미 일치. 예산이 다양성을 대행 구매한다.
6. **리터 빈 판독은 선형 전처리로 안 풀린다** — 도메인(스타일) 문제.

## 10. 현재 상태와 다음 결정

- **최적 스택**: GEN10B 가중치(`band_out/ps10b_det_neg25.pt` ·
  `reader_out/ps10b_rdr/best.pt`) + 640 추론. 정닥 56.0%·오답 1.9%·
  함정 29.0%. 제품과의 간극 13.7pp.
- **결정 대기**(상세 `docs/reports/status-2026-11-19.md` §4): 유리 분류기
  착수 → 예산 곡선(16k/24k) → 배포 갱신(ONNX 재내보내기+실기기 검증) →
  앱 MIN_FRAC 2%→1.5% → 고해상도 합성 렌더 → 종횡비 프로파일 수술.
- 실기기 카메라 경로 검증은 여전히 별도 미완(ocr_debug 증거 수집 기능은
  준비됨).
