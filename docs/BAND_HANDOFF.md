## 2. 데이터 생성

### 2.1 생성기 — `synth_panel.py`

한 장을 통째로 그린다. **사진을 한 장도 읽지 않는다** — OpenCV 도형과 DSEG
7세그먼트 벡터 글꼴로만 렌더한다.

한 장의 구성:

| 요소 | 무엇 |
|---|---|
| 기기 몸체 | 단색 플라스틱 톤 + 상하 그라디언트 + 둥근 모서리 |
| 베젤 | 홈(어두운 선) + 그림자 띠 + 가장자리 하이라이트 |
| LCD 유리 | 그 안에 7세그 숫자 + 보조 표기(단위·시각·아이콘) |
| 글레어 | streak / specular 등 유형별 |
| 대비 열화 | 잉크-패널 간극에 0.40~1.0 계수 |
| 카메라 워프 | roll ±25° (가우시안) · yaw/pitch ±20° · zoom 0.25~1.0 |
| 기기 바깥 | `--bg flat` 단색 / `--bg procedural` **절차적 배경** |

- 기기 프로파일 24종 이상(`synth_profiles.py`). 각 요소 등장 확률 60~80%
  (100% 없음 — 2026-09-17 사람 결정).
- 세로:가로 = **50:50** 강제(`set_wide_share`, `DEFAULT_WIDE_SHARE = 0.5`).
- **난수 두 갈래**: 기기 렌더용 `_orng` 와 배경용 `_brng` 가 분리돼 있다.
  `_brng` 는 `_orng` 의 씨앗을 변형해 만든다 — `rng` 를 한 번 더 뽑지 않으므로
  같은 시드에서 배경만 바꿔도 기기·자세·값이 **비트까지 동일**하다.

**절차적 배경**(`PROCEDURAL_BG`, `procedural_bg()`): 사실적 장면이 아니라
**경쟁 구조의 집합**이다. 다중 옥타브 저주파 밝기 장 · 방향성 결(줄무늬/격자) ·
기기·LCD 와 크기가 비슷한 회전 사각형/둥근 사각형/타원/굵은 선 · 어두운
테두리 안의 밝은 면(LCD 와 특징 공유) · 평행선 · 분절된 획. 초점 밖 물체와
반투명 섞음. `BG_FLAT_P = 0.15` 로 단색 배경도 일부 남긴다.
**읽히는 7세그 숫자는 만들지 않는다** — 무라벨 정답이 생기면 "이미지당 객체
1개"가 깨진다.

**기기 안쪽(버튼·각인·스트립 포트)은 아직 안 그린다.** 버튼 오인이 남아 있는
이유로 의심되는 자리다(§7 참조).

### 2.4 여백 규약 — **두 겹이다. 이걸 모르면 측정이 통째로 틀린다**

| 상수 | 값 | 어디 | 무엇 |
|---|---|---|---|
| `lcd_layout.BAND_MARGIN` | 0.10 | 라벨 | 정답 상자가 **숫자 칸을 넘어 감싸는** 여백. `0.10 × 숫자높이` 사방 |
| `lcd_layout.LAYOUT_MARGIN` | 0.10 | 그림 | 숫자가 영역 안에서 물러나는 정도. **고정**(기기 생김새) |
| `build_cache_v2.BOX_MARGIN` | (0.10,)×4 | **배포** | 검출 상자에 사방 10% 를 더해 리더에게 넘긴다 |

- 2026-09-16 에 `BAND_MARGIN` 을 그림용/라벨용으로 **갈랐다.** 그 전에는 한
  상수가 둘을 다 해서, 라벨을 키우려고 값을 올리면 **그림의 숫자가 작아졌다**.
- 사람 라벨 지침(`webtool.html:380`)이 같은 값을 쓴다: "박스 = 숫자 칸 전체
  (보통 3칸) + 사방 여백 … 여백은 숫자 높이의 10% … **잉크가 아니라 칸이
  기준**이라 빈 앞칸도 포함 … 단위·날짜·M·화살표는 넣지 않는다."
- 따라서 **사람 라벨에서 숫자 칸을 역산할 수 있다**: 라벨을 사방으로
  `라벨높이 × BAND_MARGIN/(1+2·BAND_MARGIN)` = 8.33% 줄이면 숫자 칸이다.
  합성에서 검증됨(n=1000, 변 오차 중앙 +0.006 · p90 +0.017).

> **2026-09-19 에 이걸 몰라서 사고가 났다.** `BOX_MARGIN` 을 빼고 재서 잘 되는
> 조건을 "14.3점 나쁘다"고 판정할 뻔했다. **원시 예측만으로 판정하지 마라.**

## 3. 모델 — `band_net.py`

직접 설계했다. 외부 구조·가중치를 쓰지 않는다(SPEC §5.3).

```
입력    1채널 그레이스케일 416×416 레터박스 (PAD=114)
백본    depthwise separable residual, blocks=(2,2,3,2)
        /4 → /8 → /16 → /32,  /32 를 올려 /16 과 합침
특징맵  /16 한 장 (26×26).  **stride-8 없음, FPN 없음**
헤드    ConvBN ×2 → obj(1채널) + reg(4채널, softplus)
디코드  obj 전역 argmax 하나.  **NMS 없음, 분류 헤드 없음**
파라미터 0.504M (width 1.0)
초기화  obj bias −4.595 (sigmoid≈0.01), reg bias 0
```

- `softplus` 를 쓴다 — `exp` 는 초반에 발산했다.
- 물체가 **이미지당 하나**라 argmax 로 끝난다. 문턱을 낮춰도 상자가 늘지 않고
  "검출 없음"이 "검출 있음"으로 바뀔 뿐이다.

## 4. 학습 — `train_band.py`

```bash
python train_band.py \
  --data synth_coco/TB --train-ann instances_curve_07998.json \
  --out band_out/bg/bg_s0.pt \
  --steps 8000 --batch 32 --width 1.0 --size 416 \
  --score-target bce --seed 0
```

| 인자 | 기본 | 뜻 |
|---|---|---|
| `--steps` | 6000 | **스텝 고정.** 에포크 고정은 장수와 계산량을 뒤섞는다 |
| `--radius` | 1.5 | 양성 배정 반경(칸 단위). `pos = near ∩ GT 내부` |
| `--pos-w` | 50 | objectness BCE 양성 가중치 |
| `--box-w` | 2.0 | 회귀 손실 가중치 |
| `--score-target` | bce | `bce` / `iou` / `centerness` |
| `--score-warm` | 1000 | `iou` 타깃을 1.0 에서 넘기는 스텝 |
| `--grow` | 0.0 | 정답 상자를 상자 높이의 이 비율만큼 사방 확대(적재 시점) |
| `--under-w` | 1.0 | >1 이면 **정답보다 모자란 변**에만 추가 벌점 |
| `--aug` | 꺼짐 | 광학 열화 + 배율·위치 흔들기 |
| `--seed` | 20260930 | 초기화·셔플 |

손실 = objectness BCE(가중) + `box_w` × GIoU(l,t,r,b 거리쌍).
lr 2e-3, AdamW(wd 5e-4), 코사인 + 워밍업, grad clip 10.
학습 1회 **약 600~675초**(RTX 환경 실측).

**`--grow` / `--under-w` / `--aug` 는 2026-09-19 에 추가했고 아직 한 번도
학습에 쓰지 않았다.** 스모크 테스트만 통과했다.

### 5.1 게이트 정의

- **합성**: `digit_box` 가 예측 상자에 **100% 드는가** ∧ 면적비 ≤ τ.
  **IoU 를 게이트로 쓰지 않는다**(SPEC §7-3) — 상자가 커서 IoU 가 낮은 장은
  리더에 무해하고, IoU 가 높은데 숫자를 자르는 장이 있다. 양방향으로 틀린다.
- **실촬**: 실촬에는 `digit_box` 가 없다. 사람 밴드 라벨 전체 포함 ∧ 면적비 ≤ τ.
  **이건 숫자 포함보다 엄격하다** — 숫자는 온전한데 사람 여백만 잘라도 실패한다.
  숫자 칸 기준으로 재려면 §2.4 의 역산을 쓴다(`report_fix_arms.py`).
- τ 는 **곡선으로 보고한다.** 확정은 후속 숫자 인식기의 입력 규격이 나온 뒤다.
- **배포 상자**(`BOX_MARGIN` 적용)로도 같이 재라. 원시만 재면 체계적으로 낮게 본다.

### 합성 세트 V/VB (퇴행 감시)

`bce` τ=1.2 99.71% · `bg` 99.14%. 프로파일 최저 97.66% / 96.61%. 검출 실패 0.

### 문턱

`conf` 기본 0.25 는 `bce` 의 포화된 분포(중앙 0.999, p05 0.751)에 맞춰져 있다.
`bg` 는 분포가 넓다(p05 0.013). 낮추면 검출률과 절대 품질이 **같이** 오른다:

| `bg` | conf 0.25 | conf 0.05 |
|---|---|---|
| 코퍼스 A 검출률 / 배포 게이트 | 99.3% / 79.9% | 99.7% / 80.0% |
| 코퍼스 B 검출률 / 기기 안 | 85.4% / 64.6% | 91.8% / 67.5% |

conf 0.02 에서도 코퍼스 B 는 94.1% — **6% 는 문턱으로 회수되지 않는다.**
**문턱은 지표가 아니라 제품 결정이다**("값 없음"↔"틀릴 수 있는 값").

## 7. 남은 문제 (우선순위 순)

1. **원시 예측이 숫자 칸을 24.7% 에서 자른다**(`bg`). 배포 상자로 6.1% 로
   줄지만 원시가 자르는 것 자체가 위험이다.
   → 만들어 둔 손잡이: `--grow`(정답을 키워 학습) · `--under-w`(모자란 변에만
   벌점). **아직 안 돌렸다.**
2. **버튼 오인 2.3%**(코퍼스 A 6.4장). 절차적 배경은 기기 **바깥**만 그리고
   **안쪽은 민짜**다. 생성기가 버튼·각인·스트립 포트를 그려야 잡힐 것으로
   의심되나 **검증 안 됨**.
3. **검출 실패**: 코퍼스 B 14.6%(conf 0.25). 문턱으로 대부분 회수되나 6% 잔여.
4. **학습 증강이 0이다.** SPEC §9.7.4 가 센서 잡음·JPEG·조명 불균일을 아직
   안 그린다고 적어 뒀는데, 증강으로도 안 덮고 있다. `--aug` 를 만들어 뒀다.
   **아직 안 돌렸다.**
5. **Roboflow 크기 불일치**(§6) 미해명.
6. **시드 잡음이 크다.** 실촬 성적이 시드 간 합동 SD 6.5점. t검정 기준 필요
   시드: 15점 5개 · 10점 8개 · 5점 28개. **10점 미만 효과를 3시드로 주장하지
   마라.**
