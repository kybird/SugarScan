# GEN6 — 함정 화면(코드/시각) 거절 학습 설계 (2026-11-17)

## 전제 — 문맥 판별은 프레임 층의 몫이다

밴드 규약("숫자줄만 감싼다")이 크롭에서 문맥을 제거하므로 **리더는 코드
숫자와 혈당 숫자를 영원히 구분할 수 없다**(사람 지적 2026-11-17). CODE
라벨·단위·레이아웃을 보는 유일한 층은 검출기(전체 프레임)다. 그러므로:

```text
코드 화면 거절 = 검출기 objectness 0 (모자이크 거절과 같은 메커니즘)
리더 = 변경 없음
```

근거(DC238 재판): 함정통과 판독값이 거의 전부 혈당 범위(21~140) — 값
검증이 무용하다. 제품 21/31, GEN4 9/30, GEN5 18/31 통과.

## 데이터

- 장면그룹에 **제4변형 `code`** 추가: 같은 배경·방해물·촬영에서 기기가
  **코드 화면**을 보인다. skip_digits 메커니즘의 형제(screen_mode 파라미터).
- 코드 화면 구성(실물 근거: DC238 11번 사진 On Call Plus):
  - 숫자 = **10~600 균등**(범위 내 코드가 위험 다수 — 일부러)
  - **CODE 인쇄 라벨**을 숫자 아래 LCD 에 렌더(putText, print 계열 글리프)
  - 날짜·시각 보조행 유지, **단위/식전식후 등 혈당 문맥 전부 억제**
  - 꺼짐 변형(off)과 동일하게 has_band=0, neg_reason="code_screen"
- 양성은 변동 없음(값당 균등 30~599 — 저값 30~60 양성이 이미 ~5% 포함,
  거짓 거절 방지의 짝). GEN5 광학 축(roll45·그레인·주름) 그대로.
- 발생률: 그룹당 30% 에 code 변형 생성(파라미터 code_p).

## 학습·채점

- 레시피 변경 없음: det base/neg25(width1.5·6000스텝) + rdr base60/neg.
  음성 풀에 code 변형이 섞여 들어간다.
- 채점: 동일 DC238 정답표(측정 전용) + GEN6_VAL.
- **사전 판정 기준(제안 — 결과 열람 전 확정 요망)**:
  정답 확정 ≥ GEN5(62.8%), 오답 확정 ≤ GEN5(15.9%),
  **함정통과 ≤ 30%(GEN4 수준 회복)**.

## 틀리기 쉬운 곳

1. CODE 라벨이 픽셀 신호의 전부가 되면 라벨만 보고 거절 — 실측에서
   라벨 가려진 코드 화면은 여전히 통과할 수 있다(한계로 기록).
2. 저값 실측(30~60) 오탐 위험 — 양성의 저값 비중 유지가 방어.
3. screen_mode 기본값 glucose — 기존 해시 불변(변형 없는 호출은
   코드 경로 자체가 안 타진다).
4. whitelist: CODE 라벨은 _lcd_text(백 리스트 assert)를 우회하는
   전용 렌더 경로로 — 혈당 패널 토큰 규약은 그대로.
