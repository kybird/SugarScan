# G9 — 6개 언어 글자 넘침 점검

- 브랜치: `glm/G9-locale-overflow`
- 커밋: 이 보고서와 함께 하나
- 상태: 완료 — 실제 넘침 1건을 발견·수정, 하네스 48 케이스 전부 통과.

## 방법 — 지시서에서 바꾼 한 가지

무인 세션은 화면을 눈으로 돌아볼 수 없어 **Windows 데스크톱 빌드 경로를
대신했다.** 대신 이 앱의 객관 신호를 쓴다 — RenderFlex overflow 는 프레임워크가
`FlutterError` 로 보고하고 위젯 테스트는 그것만으로 실패한다.

`test/app/locale_overflow_test.dart`(신규):

- **8개 화면** — 대시보드·기록 목록·통계(하단 스크롤 포함)·설정(하단 스크롤
  포함)·단위 확인 온보딩·스캔(카메라 없음 경로, 타임아웃 펌프)·직접 입력
  시트·저장 확인 시트.
- **6개 언어** en·ko·es·pt·de·fr — `MaterialApp.locale` 로 고정(지시서가 제시한
  방식).
- **뷰포트 390×844**(일반 안드로이드 논리 폭) — 8×6 = **48 케이스**.
- 기록 2건(짧은 메모·긴 메모 포함)을 심어 실제 내용이 그려진 상태에서 잰다.

이 파일이 통과하면 넘침이 없다는 기계적 증거가 되고, 실패하면 넘침 보고가
된다. 덕분에 `flutter create --platforms=windows` 의 되돌림 대상(위젯 테스트
템플릿·`.metadata`)도 생기지 않았다.

**한계(정직하게 적는다)**: 넘치지 않으면서 어색한 배치(간격·정렬 위주)는 이
신호로 안 잡힌다 — 눈으로 보는 검수는 사람 몫으로 남는다.

## 발견과 수정

### 통계 요약 카드 — 유일한 실제 넘침

- **증상**: 통계 화면이 en(0.5px)·es·pt·de(최대 15px)에서 넘친다. ko·fr 는
  통과. 하네스 첫 실행에서 4개 언어 실패로 잡혔다.
- **원인**(위젯 트리 덤프로 특정): 요약 카드의 바깥 `Row [Expanded(평균 블록),
  Text(건수)]` — 건수 문구가 긴 언어("2 Messwerte")가 `Expanded` 를 몰아세워
  안쪽 **값+단위 행**("120 mg/dL", baseline 정렬)의 폭을 자연 폭 아래로 눌러
  넘친다.
- **수정**: 바깥 `Row` → `Wrap`(지시서 방식 ③) + 안쪽 값 Row 에
  `mainAxisSize: min`(Wrap 이 자식에게 무제한 폭을 주므로 max 기본값이면
  무한히 퍼지려 해 다시 줄넘김 — 첫 시도에서 그래프 첫 화면 테스트가 깨져
  실측으로 붙잡았다). 건수 문구가 길면 평균 블록 아래 줄로 흘러간다.
- **값·단위는 자르지 않는다** — 수정은 줄바꿈만 일으킨다(지시서의 붉은 선).
  값이나 단위가 잘리는 자리는 없었다.

첫 시도로 `Flexible`(방식 ②)로 건수를 감쌌다가 **악화**했다(17px, 전 언어) —
`Expanded`·`Flexible` 이 flex 를 공유해 이등분했기 때문. 되돌리고 방식 ③으로
갔다. 이 경로도 보고서에 남긴다.
