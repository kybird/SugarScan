# 작업 보고서

[`../GLM_TASKS.md`](../GLM_TASKS.md) 의 각 작업이 끝나면 여기에 보고서가 쌓인다.
파일명은 지시서가 작업마다 지정한다(`G1-unused-l10n-keys.md` 형식).

보고서는 **지운 기록이 아니라 남기는 기록**이다. 나중에 "왜 이렇게 되어 있지"를
물었을 때 답이 여기 있어야 한다. 특히 다음 둘은 비워 두지 말 것:

- **검증** — 실행한 명령과 그 출력. 돌리지 않고 채우면 안 된다.
- **건드리지 않고 남긴 것** — 이상해 보였지만 지시 범위 밖이라 둔 것.
  다음 작업 목록이 여기서 나온다.

## 병합한 뒤에 할 일

보고서는 작업 단위 기록이고, 프로젝트 이력의 정본은
[`IMPLEMENTATION_PLAN.md`](../IMPLEMENTATION_PLAN.md) **§15 구현 로그**다.
작업을 `main` 에 병합했으면 **결과를 정본으로 되먹여야 한다.** 이 단계를
빠뜨리면 이력이 W 계열과 G 계열로 갈라져, 다음에 오는 사람이 §15 만 읽고는
"언제 왜 이렇게 됐나"를 찾지 못한다(G1~G8 에서 실제로 그렇게 됐다).

1. **§15 에 한 항목** — 나중에 다시 물을 만한 것만. 보고서를 옮겨 적지 말 것.
2. **[`CLAUDE.md`](../../CLAUDE.md)** — 새로 생긴 규약·함정, 그리고 "현재 상태".
   여기 반영되지 않은 변경은 다음 세션의 에이전트에게 존재하지 않는 것과 같다.
3. **[`GLM_TASKS.md`](../GLM_TASKS.md)** — 완료 표시와 병합 해시. 뒤이은 작업의
   지시문에 남은 옛 숫자(키 수 등)도 이때 함께 고친다.
