## 무엇을 했나

- `tools/synth7seg/bin/synth.dart` 신규 작성 — 혈당계 표시 전체(장면)를
  임의로 그려 `images/000001.png …` + `labels.jsonl` 을 낸다.
- 글리프 비트표는 `lib/ocr/testing.dart` 가 export 하는
  `kDigitPatterns` / `kLetterPatterns` 를 그대로 import 해서 썼다.
  손으로 옮겨 적지 않았다. `lib/` 는 한 줄도 안 고쳤다.
- 세그먼트 위치는 판독기(`SegmentGeometry`)와 무관한 일반 비율로 따로
  정의했다(셀 폭 = 높이의 1/2, 간격 = 폭의 0.35, 굵기 = 폭의 1/6).
- 변화 축은 지시서의 숫자 그대로: 자릿수 3/4 · mg/dL 20~600 · mmol/L
  1.1~33.3(소수 1자리) · HI/LO 8% · 여백 0~25% · 회전 ±8° · 원근 0~6% ·
  대비 30~200 · 블러 0~1.5px · 반사 15% · 극성 반반.
- 기본 2000장을 `assets_dev/synth` 에 생성했다(G17 입력용).

## 왜 그렇게 했나

- **패턴 테이블 import 경로** — `testing.dart` 가 이미 `segment_patterns.dart`
  전체를 export 하고 있어서 경계(§2.1)를 준수한 채 표를 직접 쓸 수 있었다.
  `lib/` 를 고쳐 export 를 추가할 필요가 없었다.
- **`I`/`O` 글리프** — `kLetterPatterns` 에는 `L`·`H` 만 있다. 표의 주석이
  "`O` 와 `I` 는 각각 `0`, `1` 과 세그먼트 패턴이 완전히 같다"고 명시하므로
  HI/LO 렌더링에 `kDigitPatterns[1]`/`kDigitPatterns[0]` 을 썼다.
- **원근은 캔버스 전체 모서리로** — 표시 블록이 아니라 장면(캔버스) 네
  모서리를 흔들어 전체 호모그래피를 걸었다. "비스듬히 본 화면"에 가깝고,
  사각형 내외 판정 없이 역매핑 하나로 끝난다.
- **배경 휘도는 난수로 안 뽑는다** — 전경·배경 차가 라벨의 `contrast` 와
  정확히 일치하도록 극성별로 결정적으로 계산했다. G17 이 축별 분해를 할 때
  라벨을 그대로 믿을 수 있어야 한다.
- **난수는 `_Sample.draw` 한 곳에서만** — 렌더 중에 난수를 소비하면 순서가
  두 벌이 되어 재현이 깨진다. 모서리 오프셋·글레어 파라미터도 표본 생성
  시점에 몰아 뽑는다(글레어는 당첨 여부와 무관하게 항상 뽑아 분기가 소비
  순서를 갈라지지 않게 한다).

## 발견해서 고친 버그 — 소수점이 그려지지 않았다

첫 눈 검증에서 소수점 라벨 4건(`5.4`·`23.0`·`13.2`·`6.0`)의 점이 전혀
보이지 않았다(비전 모델 4/4 "점 없음"). 원인은 `_inkAt` 의 갭 판정 —
`_inDecimalDot` 에 **갭 시작 기준 오프셋**을 넘겨야 하는데 **셀 시작
기준 값**(셀 폭 이상)을 그대로 넘겨 x 범위 비교가 영원히 거짓이었다.
소수점이 있는 장면은 전부 라벨-이미지 불일치 상태로 나오던 것이었다.
한 줄 수정(`inCellX - cellW`) 후 재생성·재검증했다.
