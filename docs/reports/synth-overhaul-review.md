## 통과 — 근거와 함께

### 1. 자를 움직이지 않았다

`measure_panel_stats.py`(+39) 와 `measure_polarity.py`(+28) 가 바뀌어 가장
먼저 봤다. **순수 리팩터링이다.** `collect_aspect` · `collect_band` ·
`collect_density` · `collect_polarity` 를 추출해 정본 생성기
(`make_real_baseline.py`)와 CLI 가 같은 코드를 쓰게 했다. 임계·ROI·공식이
하나도 바뀌지 않았다.

읽는 것으로 끝내지 않고 브랜치 자로 실사진을 다시 쟀다. **한 자리도 움직이지
않는다.**

```
python measure_panel_stats.py density --frame-exc 0
  n=264  density median=0.0177 p10=0.0046 p90=0.0384
python measure_polarity.py
  n=264  inverted=89 (33.7%)   밴드 대비 median=99 p10=60 min=21 (<40: 1.1%)
python measure_panel_stats.py band

```

방향이 옳다. 이 저장소가 2026-09-12 에 겪은 사고(같은 축을 두 주체가 각자
재서 7.51% 와 2.25% 가 나란히 인용됨)를 **구조적으로 막는** 변경이다.

## 지적

### A. 글리프 평면 자가검사가 무력화됐다 (심각)

`glyph_plane_check` 가 크게 나빠졌다.

| | 병합 전(main) | 이 브랜치 |
|---|---|---|
| median | 0.9997 | 0.9989 |
| p10 | 0.9908 | **0.9384** |
| min | 0.7043 | **0.0000** |
| 0.9 미만 | 0.8% | **8.7%** (n=300) |

GLM 은 보고서에 "gpc<0.9 는 저대비 렌더의 잉크 문턱 반영" 이라 적었다.
**그 진단은 맞다.** 최저 6장을 오버레이로 확인하니 전부 저대비 패널이고
**쿼드는 정확히 숫자에 붙어 있다** — 기하 회귀가 아니다.

원인을 수치로 확정했다. 패널 대비와 gpc 가 단조 관계다.

| 대비(p95-p5) | n | gpc median | 0.9 미만 |
|---|---|---|---|
| 0~40 | 3 | 0.764 | 66.7% |
| 40~60 | 21 | 0.953 | 33.3% |
| 60~80 | 45 | 0.984 | 20.0% |
| 80~120 | 147 | 0.999 | 4.1% |
| 120+ | 84 | 1.000 | 2.4% |

`glyph_plane_check` 는 `ink = |img - bg| > 30` 이라는 **고정 문턱**을 쓴다.
열화 상한 카드가 대비 분포를 의도적으로 아래로 넓혔으므로(실사진 p10 60 ·
40미만 1.1% 를 맞추려고) 저대비 패널에서 잉크가 문턱을 못 넘는다.

**그래서 이게 지적이다.** 검사가 "글리프 평면이 어긋났다" 와 "패널이 흐리다"
를 구별하지 못한다. 2026-09-12 리뷰에서 이 검사가 살아 있는지 확인했던
방법(글리프 평면을 8px 어긋뜨리면 median 0.9997 → 0.8337)이 이제 저대비
패널에서는 무의미하다 — 어긋나지 않아도 그 아래로 떨어진다.

**고칠 방향**: 잉크 문턱을 패널의 실제 대비에 비례시킨다(예: `p95-p5` 의
일정 비율). 고정 30 을 쓰는 한 대비를 넓힐수록 이 검사는 못 쓰게 된다.
판단이 필요한 자리라 내가 고치지 않았다 — 자가검사 정의 변경은 카드가
금지한 행위이기도 하다.

**병합 자체를 막지는 않는다.** 산출물은 정상이고(쿼드 정확, 하드 검사 0)
망가진 것은 검사의 분해능이다. 다만 **고치기 전에는 이 검사 통과를 근거로
쓰면 안 된다.**

### B. 2자리 표본이 작다

위 2자리 측정의 `n=32` 이고 `p10 0.637` 로 넓다. 중앙값은 결론을 지지하지만
관례를 뒤집는 변경치고는 표본이 얇다. 밴드 라벨이 더 쌓이면 다시 볼 것.

### C. 극성은 미결이다 (알려진 것)

합성 극성 48.3%(n=120) / 실사진 33.7%. 이 축은 조정으로 닿지 않는 것이
2026-09-13 새벽에 밝혀져 별도 카드로 분리했고 사람 결정 대기다 —
「합성 프로파일 세트가 기기 모집단을 대표하지 않는다 — 극성이 그 증상」.
이 브랜치의 결함이 아니다.

## 확인하지 못한 것

- 가로형 렌더(측면 칼럼형·하단 행형)를 **눈으로 보지 않았다.** n=300 에서
  가로형은 25장이고 gpc 0.9 미만이 12.0%(세로형 8.4%)로 세로형보다 높다.
  표본이 작아 판단을 보류한다. 가로형 전용 몽타주로 봐야 한다.
- `flutter analyze` / `flutter test` 를 돌리지 않았다. 이 브랜치는 파이썬만
  바꾼다(GLM 보고에는 analyze 무경고 · test 471 통과로 적혀 있다).
- 보고서 5편의 내용을 한 줄씩 대조하지 않았다. 수치는 재현했다.
