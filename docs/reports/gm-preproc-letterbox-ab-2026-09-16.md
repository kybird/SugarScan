# GM 검출 추론 전처리 A/B — 스트레치에서 레터박스로 (2026-09-16)

재학습 없음. 체크포인트는 `yolox_out/gmscreen_ft3/best_ckpt.pth` 하나로 고정하고
**추론 전처리만** 바꿔 잰다.

## 어긋남이 둘이었다

카드는 기하 하나(스트레치 vs 레터박스)를 지목했는데, 코드를 읽으니 채널 순서도
어긋나 있었다.

| 축 | 학습(YOLOX) | 기존 추론(`detect_datumo_gm.py`) |
|---|---|---|
| 기하 | 레터박스 — `r = min(비율)`, 남는 자리 114 회색 (`data_augment.py:142-155`) | `cv2.resize(img0,(imgsz,imgsz))` 스트레치 |
| 채널 | BGR — 로더가 `cv2.imread` (`datasets/coco.py:148`), preproc 는 채널을 안 바꾼다 | `img[..., ::-1]` 로 RGB |

파일 머리말에 적혀 있던 "YOLOX evaluator와 동일 전처리: 스트레치+BGR" 은 **두
군데 다 사실이 아니었다.** 두 축을 한 번에 바꾸면 어느 쪽이 움직였는지 알 수
없으므로 `--preproc` 로 갈라 세 팔로 잰다.

- `stretch` — 기존 경로 그대로(스트레치 + RGB). 기본값이라 동작이 안 바뀐다
- `letterbox` — 기하만 맞춤(레터박스 + RGB)
- `yolox` — 둘 다 맞춤(레터박스 + BGR). `ValTransform` 과 같은 그림

## 재현

```bash
cd assets_dev/train
python detect_datumo_gm.py --selftest          # yolox 모드 == YOLOX preproc 대조
for m in stretch letterbox yolox; do
  python detect_datumo_gm.py --preproc $m \
    --ckpt yolox_out/gmscreen_ft3/best_ckpt_np1.pth --imgsz 416 \
    --out _diag/preproc_ab/$m.jsonl
done
python gm_preproc_ab.py \
  --arm 운영=gmscreen_quads.jsonl \
  --arm letterbox=_diag/preproc_ab/letterbox.jsonl \
  --arm yolox=_diag/preproc_ab/yolox.jsonl --wide-detail
```

`*_np1.pth` 는 `migrate_ckpt_numpy1.py` 로 연 체크포인트다 — 원본은 numpy 2.x 로
절여져 지금 환경에서 `ModuleNotFoundError: No module named 'numpy._core'` 로
안 읽힌다. 가중치는 같다.

### 기준선을 먼저 맞췄다

`stretch` 팔이 운영 `gmscreen_quads.jsonl` 과 **좌표까지 동일**하다(앞 40장
전수 대조, 최대 좌표차 0.0). 즉 이 리팩터링은 기존 경로의 동작을 바꾸지 않았고,
아래 표의 `운영` 과 `stretch` 는 같은 줄이다. 운영 파일을 만든 체크포인트가
`ft3/best_ckpt` 라는 것도 이 대조로 확정했다(카드가 적어 둔
`gmscreen/latest_ckpt.pth` 는 2026-09-12 ft3 승격 이전의 기록이라 낡았다).

# 2026-09-17 정정 — 채널 축을 잘못 읽었다

이 보고서의 초판은 가로 층에서 `yolox`(채널까지 맞춘 팔)가 `letterbox` 보다
나쁘다고 적고, 그 근거로 **1826 한 장이 IoU 0.526 → 0.039 로 무너지는 것**을
들며 "채널 축의 불안정성"이라고 했다. **그 귀속이 틀렸다.**

## 무엇이 틀렸나

층별 중앙값만 보고 판정했다. 같은 장에서 짝지어 보면 그림이 다르다.

```bash
python gm_preproc_ab.py \
  --arm letterbox=_diag/preproc_ab/letterbox.jsonl \
  --arm yolox=_diag/preproc_ab/yolox.jsonl \
  --paired letterbox yolox
```

| 층 | n | yolox 승 | 패 | 무 | 짝차이 중앙 | 짝차이 평균 |
|---|---:|---:|---:|---:|---:|---:|
| 전체 | 405 | 161 | 95 | 149 | +0.0032 | +0.0080 |
| 가로 | 42 | 5 | 14 | **23** | −0.0044 | −0.0195 |
| 세로 | 363 | 156 | 81 | 126 | +0.0054 | +0.0112 |

가로에서 **절반 이상이 무승부**이고, 중앙값(−0.004)과 평균(−0.020)이 다섯 배
갈린다. 꼬리가 평균을 끌고 있다는 신호다. 가장 나빠진 세 장이
1826(−0.487) · 1598(−0.209) · 1596(−0.183) 이고, 1826 하나가 42장짜리 층의
평균을 혼자 움직인다.

## 1826 이 무너진 진짜 이유

```bash
python diag_gm_candidate_tie.py --ids glucose_batch1/1826,glucose_batch1/1598
```

```text
── glucose_batch1/1826 (3024x4032)
  두 입력 픽셀차: 평균 3.37 · max 42  (0~255)
  화면 밖 포함 |R-B| 평균: 6.7
  letterbox:
     점수 0.2536  상자    2417x2920    ← 기기 전체
     점수 0.2528  상자     463x455     ← 작은 조각
     -> 1·2위 점수차 0.3% (근접 동점) · 넓이비 33.5배
  yolox:
     점수 0.2738  상자     460x450     ← 순위가 뒤집혔다
     점수 0.2391  상자    3027x3238
```

두 가지가 동시에 성립한다:

1. **두 입력이 거의 같다.** 픽셀 평균 차 3.37/255. 이 사진은 거의 무채색이라
   (|R−B| 평균 6.7) R↔B 를 바꿔도 화소가 거의 안 변한다. 채널 순서가 이
   장에서 그림을 바꿨다고 말할 수 없다.
2. **후보 두 개가 0.3% 차이로 붙어 있고 넓이가 33.5배 다르다.** 하나는 기기
   전체, 하나는 작은 조각이다. 이 상태에서는 무엇이든 조금만 흔들면 top-1 이
   뒤집히고, IoU 0.526 과 0.039 는 그 두 상자 사이의 거리일 뿐이다.

대조군으로 1598 을 같이 보면 구별이 분명하다 — 그쪽은 입력 차가 더 큰데도
(평균 12.98) 1위가 77% 차로 명확해서 상자가 안 뒤집힌다.

## 고쳐 쓴 결론

- 채널 순서 불일치는 **우리 코드의 실제 버그가 맞다**(학습 BGR / 추론 RGB).
  고친 방향은 **작지만 양수**다 — 세로 156승 81패, 전체 161승 95패.
- 가로의 손해는 축의 효과로 읽을 근거가 약하다. 무승부가 23/42 이고 평균은
  이상치 한 장이 만든다. n=42 에 이상치 하나로 축을 기각하지 않는다.
- **1826 이 가리키는 것은 채널이 아니라 검출기의 근접 동점이다.** 기기 전체와
  작은 조각이 0.3% 차이로 경쟁하는데 우리는 top-1 을 그대로 받는다. 종횡비나
  넓이 같은 최소한의 제정신 검사가 없다. 이쪽이 채널 축보다 크다.

## 왜 처음에 틀렸나

층 중앙값 하나로 축을 판정했고, 그 층의 n 이 45 이며 이상치가 하나 있다는
것을 함께 보지 않았다. 같은 날 다른 카드에서 「문턱 세기가 연속량의 이동을
삼킨다」를 지적해 놓고, 여기서는 반대 방향 — **꼬리 하나가 중앙값을 대신해
읽히는 것** — 을 놓쳤다. `--paired` 를 자에 넣은 이유가 이것이다.
