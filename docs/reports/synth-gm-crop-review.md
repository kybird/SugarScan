## 2. 지시서가 짚은 자리 — 하나씩

### 2-1. 자를 움직인 것인가 (지시서 1)

**(a) `glyph_plane_check` 배경 추정 변경 — 자를 움직인 것이 아니다. 검사는 여전히 실패할 수 있다.**

브랜치 공식을 그대로 옮겨 쓰고 `sel`(글리프 평면)만 일부러 밀었다. 내 재계산이
manifest 값과 일치하는 것(median 0.9995 vs 0.9996)이 공식을 옳게 옮겼다는 증거다.

```
n=40
  manifest         median=0.9996 p10=0.9904 min=0.9702
  recomputed dx=0  median=0.9995 p10=0.9904 min=0.9702
  dx=8             median=0.7198 p10=0.5718 min=0.4390
  dx=16            median=0.4698 p10=0.3096 min=0.1380
  dx=32            median=0.3307 p10=0.2410 min=0.1162
  dy=32            median=0.5382 p10=0.4191 min=0.3911
  dx=dy=64         median=0.1285 p10=0.0597 min=0.0185
```

8px(획 하나 폭)만 어긋나도 median 이 1.00 → 0.72 로 떨어진다. **무력화되지 않았다.**

나아가 같은 렌더에서 배경 추정만 구판(`np.median(img)`)으로 갈아 끼워 봤다.
차이가 거의 없다 — 즉 이 변경은 지표를 올리려는 것이 아니었다:

```
  branch     n=300 median=0.9997 p10=0.9911 min=0.7134 <0.5=0.0%
  main       n=300 median=0.9996 p10=0.9877 min=0.7001 <0.5=0.0%
  branch_s8  n=300 median=0.7341 p10=0.5992 min=0.3583 <0.5=3.3%
  main_s8    n=300 median=0.7279 p10=0.5958 min=0.3600 <0.5=3.0%
```

(이 실행의 min 0.7134 가 GLM 이 보고한 0.713 이다 — 보고 수치는 맞다. 다만 같은
시드 다른 실행에서 min 0.2357 이 나온다. §지적 5.)

**(b) `PITCH_RATIO` 0.60 → 0.56 — 지표 맞추기다.**

보고서의 사유가 그대로 자백이다: "피치가 클수록 밴드 높이가 깎여 band_h median 이
0.437 에 그쳤다 … 줄이니 0.443~0.448 로 회복." 실사진에서 피치를 다시 잰 기록이
없고, 저장소에 피치를 재는 자도 없다(밴드 라벨은 밴드 상자만 준다).

그리고 파일이 지금 자기모순이다. 같은 파일 머리말(`synth_panel.py:46`)은 손대지
않아 이렇게 남아 있다:

```
#   칸 폭    실사진 밴드 크롭 육안 + DSEG 측정: 칸 피치 ≈ 0.50~0.60·높이,
```

상수는 0.56, 머리말의 근거는 0.60 이다. **되돌리라는 뜻이 아니다** — 근거를
실측으로 다시 세우거나, 세울 수 없으면 머리말을 고쳐 "band_h 를 맞추려 좁혔고
피치 자체를 재지는 않았다" 고 적어야 한다. 판단이 필요한 자리라 내가 고치지 않았다.

**(c) `band_cy` 를 `u**1.6` 으로 — median 은 맞았고 위쪽 꼬리는 눌렸다.**

| cy | 실사진(n=51) | before(n=275) | after(n=267) |
|---|---|---|---|
| median | 0.391 | 0.416 | **0.397** |
| p10 | 0.360 | 0.377 | **0.364** |
| p90 | 0.460 | 0.454 | **0.445** |

median 과 p10 은 좋아졌고 p90 은 0.454 → 0.445 로 실사진(0.460)에서 더 멀어졌다.
크지 않지만 "median 만 맞추고 모양이 달라졌다" 는 지적이 부분적으로 성립한다.

**(d) 밴드 기하 분모를 패널 → 캔버스로 재앵커 — 옳다.**

실사진 쪽 분모를 코드로 확인했다. `measure_panel_stats.cmd_band` 은
`gx0..gy1 = _rect_of(g["quad"])` 로 **GM 쿼드**를 분모로 쓴다(`measure_panel_stats.py:80-88`).
그리고 합성 캔버스는 처음부터 GM 박스를 모사하도록 설계돼 있다 —
`synth_panel.py:23` "최종 캔버스 w/h 는 GM 박스 실측 분포", `ASPECT_BINS` 주석
"GM 박스 w/h 실측 히스토그램(2,497장)". `cmd_synth_band` 은 이미지 전체(W,H)를
분모로 쓴다. 따라서 **캔버스가 GM 박스의 대응물이고, 재앵커가 두 분모를 일치시킨
것**이다. 구판의 패널 분모가 오히려 어긋나 있었다.

곁다리: `cmd_synth_band` 독스트링이 이제 거짓이다 —
"패널 = 이미지 전체(합성은 패널만 렌더한다)". 이 카드의 전제가 바로 "합성은 이제
패널만이 아니다" 이다. 수치는 옳고 사유만 낡았다(§지적 7).

### 2-3. 안쪽 밀도 상한 (AC#4) — 정의는 이동하지 않았다

`diag_density_where.stat_ring` 을 읽었다(`diag_density_where.py:68-78`). 링은

1.30~1.36% (상한 1.70). **통과.**

### 2-7. 숨은 결함 수정이 이 카드 범위인가 — 정당하다 (표현은 한 군데 정정)

`fillc` 경계 채움 결함은 **main 에서는 재현되지 않는다.** main 은
`bezel_col = int(rng.uniform(40, 90))` 이라 항상 127 미만이고, 검사의 문턱이
`glyph_warped > 127` 이라 경계 채움이 `sel` 에 절대 안 들어간다. 즉 **구판에서
터질 수 없는 잠복 결함**이고, 몸체색(50~190)을 넣는 이 브랜치가 처음 깨우는 것이다.
GLM 의 보고("구판은 베젤색이 항상 127 밑이라 우연히 안 터진 숨은 결함")는 정확하다.

브랜치 코드에서 `border=0` 한 인자만 되돌려 A/B 했다(같은 시드, n=120):

```
border=0 (branch)        n=120 median=0.9997 p10=0.9942 min=0.9397 below0.5=0.0%
border=fillc (pre-fix)   n=120 median=0.9990 p10=0.6140 min=0.1808 below0.5=9.2%
```

고치지 않았다면 9.2% 의 패널에서 AC#2 의 자가검사가 무너진다. **이 카드에서 고치는
것이 맞다.** 다만 "구판의 숨은 결함" 이라는 표현은 "구판에 있었으나 구판에서는

## 3. 지적 — 심각도 순

### 지적 1 (심각) — 가로형에서 밴드 쿼드가 유리를 넘어 기기 몸체로 나간다

`band_h = band_h_frac * H` 로 분모를 캔버스로 옮겼는데(`synth_panel.py:481`),
가로형 `h` 범위가 (0.690, 0.865)다. 상하 몸체 스트립이 3~14% 를 먹고 나면
`0.865 × H` 가 유리 높이를 넘는다. 폭에는 `max_w = int(pw * 0.96)` 클램프가 있지만
**높이에는 대응 클램프가 없다.** `y0` 클램프는
`max(py0+2+pad_y, min(py1-2-pad_y-dh, y0))` 라 밴드가 유리보다 높으면 `max` 가 이겨
아래로 넘친다.

구판 주석이 정확히 이 위험을 경고했는데("캔버스 기준으로 뽑으면 … 패널 안쪽
클리핑이 난다") 브랜치가 "클램프+max_w 축소가 흡수한다" 며 지웠다. max_w 는 폭만 잡는다.

재현 (워프 전 좌표계, `margins` 로 유리 사각형 복원, seed 31000, n=600):
```
branch: 밴드 쿼드가 유리 밖 — portrait 0/548 (0.0%)  wide 3/52 (5.8%)  최대 초과=24px
main:   밴드 쿼드가 유리 밖 — portrait 0/546 (0.0%)  wide 0/54 (0.0%)  최대 초과=0px
```

실제 사례 하나(seed 23000, i=101, `acura_plus`):
```
rect=band (19,54,715,677)  유리=(17,52,862,660)  W,H=896,758  초과=18.0px
```
유리 높이 608px 인데 쿼드 높이가 623px 다.

**왜 심각한가**: 검출기가 "밴드 = 숫자줄" 이 아니라 "밴드 = 숫자줄 + 몸체 조각"
으로 배운다. 카드의 목적이 학습 입력과 추론 입력을 같은 물건으로 만드는 것인데,
바로 그 라벨이 틀어진다. AC#2 직격이다.

빈도는 전체의 약 0.5%(가로형이 코퍼스의 9~11%)다.

### 지적 2 (심각) — 저장소의 하드 검사 스크립트가 "카드 완료 아님" 을 찍는다

`validate_synth_panel.py` 는 이 렌더러의 AC 자다("하드 실패(0 이어야): … 요소 패널
이탈"). 브랜치 렌더러로 돌리면:

```
$ python validate_synth_panel.py --count 120 --seed 23000 --out <tmp>   # import 만 브랜치로
-- 하드 검사: {'overlaps': 0, 'quad_out': 0, 'long_side': 0, 'label': 0, 'clipped': 108, 'bezel_inside': 0}
하드 실패 1건 이상 — 카드 완료 아님
```
main 렌더러로는:
```
-- 하드 검사: {'overlaps': 0, 'quad_out': 0, 'long_side': 0, 'label': 0, 'clipped': 0, 'bezel_inside': 0}
하드 검사 전부 0
```

원인은 `validate_synth_panel.py:76-79` 가 스칼라 `m` 을 **사방 균일 여백**으로 쓰는데,
브랜치가 `margin = max(mg_t, mg_b, mg_l, mg_r)` 로 바꿔서다. 상하 여백(중앙값 83px)이
좌우(1~7%)에도 적용돼 정상 배치가 이탈로 잡힌다.

108건 중 **107건은 이 거짓 양성이고 1건은 진짜**다(= 지적 1). 같은 120장을
비대칭 여백으로 고친 검사로 다시 재면:
```
n=120  스칼라 margin 검사(현행 validate) 실패=108  비대칭 margins 로 고친 검사 실패=1  최대 초과=18.0px
```

**보고서가 이 스크립트를 돌린 기록이 없다.** 돌렸으면 지적 1 이 그 자리에서
잡혔다. 카드를 done 으로 닫기 전에 저장소의 하드 검사가 통과하는지 봤어야 한다.

### 지적 3 (중간) — 링 밀도 상승의 절반은 몸체가 아니라 선택 편향이다

`render_panel` 은 최대 3회 렌더해 **밀도가 가장 높은 것**을 고른다
(`synth_panel.py:340-346`, 구판부터 있던 로직). 몸체가 밀도의 큰 축이 되면서, 이
선택이 이제 **여백 분포 자체를 왜곡**한다. 몸체가 얇은 타이트 크롭이 계통적으로 탈락한다.

같은 시드(31000, n=300)에서 재시도 루프만 `range(1)` 로 바꿔 재면:

| | 선택 있음(브랜치 그대로) | 선택 없음(단발) |
|---|---|---|
| 타이트 크롭 비율 | **15.3%** | 31.7% |
| 바깥 링 | 3.11~3.18% | **2.22%** |
| 전체(밴드 밖) | 2.63~2.71% | **1.96%** |

코드 주석은 "30% 는 타이트 크롭" 이라고 적었지만 출력 분포는 15.3% 다.
그리고 링 1.73 → 2.97% 라는 성과 중 몸체 렌더 자체의 기여는 절반쯤이다.

구판에도 같은 편향이 있었지만 약했다(느슨한 크롭 명목 35% → 출력 39.7%;
`margin` 중앙값 7px). 브랜치에서는 레버가 커져 30% → 15.3% 로 반토막 난다.

**왜 문제인가**: 실사진 GM 크롭에는 타이트한 것도 있는데 학습 코퍼스가 두꺼운
몸체 쪽으로 계통적으로 기운다. 또 AC#3·#5 수치가 "우리가 뽑기로 한 분포" 가
아니라 "밀도로 걸러낸 분포" 에서 나온다.

판단이 필요한 자리라 고치지 않았다(선택 로직을 손대면 밀도 AC 가 전부 다시 열린다).
별도 카드 감.

### 지적 4 (중간) — AC#3 은 현재 기준선으로는 통과하지 못한다

라벨이 84 → 112장으로 늘며 실사진 링이 2.84% → 2.53% 로 내려갔다(§0).

| | 카드 당시 (n=83) | 현재 (n=111) |
|---|---|---|
| 실사진 링 | 2.84% (허용 2.34~3.34) | 2.53% (허용 2.03~3.03) |

지금 당장 실패로 보기는 어렵다 — 라벨링이 진행 중이라 기준선이 계속 움직인다.
**라벨링이 끝난 뒤 링 목표를 다시 고정하고 AC#3 을 재판정할 것**을 권한다.

### 지적 5 (중간) — 같은 시드가 같은 수치를 내지 않는다. 보고 수치와 내 수치가 다르다

`generate()` 는 `random.Random(seed0)` 만 심고 numpy 전역은 안 심는다
(`synth_panel.py:1007`). 그런데 광학 잡음이 `np.random.normal` 이다
(`synth_panel.py:816`). 형제 스크립트 `validate_synth_panel.py:46` 은
`np.random.seed(args.seed)` 를 제대로 한다 — 이 파일만 빠졌다.

같은 명령(`gen --count 300 --seed 31000`) 두 실행:

| 축 | 실행 A | 실행 B | GLM 보고 |
|---|---|---|---|
| 바깥 링 | 3.18% | 3.11% | **2.97%** |
| 안쪽 | 1.36% | 1.30% | **1.39%** |
| 전체(밴드 밖) | 2.71% | 2.63% | **2.69%** |
| ring n | 299 | 297 | 299~300 |
| glyph min | **0.2357** | 0.8076 | **0.713** |
| glyph <0.5 | 0.7% | 0.0% | — |

`panel_31000_117` 한 장의 `glyph_plane_check` 가 실행마다 0.2357 / 1.0 / 0.9555 로
튄다. 저대비 패널에서 잉크 문턱(`|img-bg| > 30`)이 잡음에 좌우돼서다. 즉
**보고서의 `min 0.713` 도, 내가 본 `min 0.2357` 도 한 번 뽑은 표본**이고 `min` 은
믿을 통계가 아니다. 링·전체 밀도의 실행 간 폭(약 0.1pp)은 AC 허용폭(±0.5pp)보다

설명되는 범위다 — **다만 "잰 값 옆에 그 값을 내는 명령을 적는다" 는 규칙이,
그 명령이 같은 값을 다시 내지 못하면 반만 지켜진 것**이다.

`np.random.seed(seed0)` 를 넣어 보면 300장 중 244장이 바이트 동일까지 회복하지만
완전하지는 않다. `render_panel` 의 재시도 루프가 **밀도 값으로 rng 소비 횟수를
가르기** 때문이다 — 1e-5 의 부동소수 흔들림 하나가 재렌더 횟수를 바꾸고, 그 뒤
패널이 전부 어긋난다. `cv2.setNumThreads(1)` 로도 안 잡혔다. **이 카드 범위를
넘으므로 고치지 않았다. 별도 카드 감.**

## 4. 잘 된 것

- **전제를 다시 세운 것이 이 작업의 핵심 성과다.** 앞 카드가 "합성 패널 vs 실사진
  GM 크롭" 이라는 서로 다른 물건을 비교하다 superseded 됐는데, 이 카드는 그
  비대칭을 렌더러에서 없앴다. 링/안쪽 분해라는 진단이 옳았고 처방도 그 진단을 따랐다.
- **폭 결정을 실측 제약에서 역산했다.** "링 15% 균일 확대" 라는 직관적 답 대신
  `band_w/canvas 0.827` 이 유리 폭 하한을 강제한다는 것을 짚고 비대칭 스트립을
  골랐다. 링 폭 무관성 4점을 내가 다시 재도 재현된다(§2-4).
- **분모 재앵커가 옳다.** 실사진 쪽 분모가 GM 쿼드라는 것을 코드로 확인했고
  (`cmd_band:80`), 합성 캔버스가 GM 박스의 대응물이라는 것도 파일 머리말과
  `ASPECT_BINS` 근거로 확인된다. 구판이 틀렸던 것을 바로잡았다.
- **`glyph_plane_check` 는 무력화되지 않았다.** 8px 밀면 median 0.72 로 떨어진다.
  배경 추정을 구판으로 되돌려 봐도 차이가 없다 — 지표 맞추기가 아니다.
- **`border=0` 수정은 진짜 결함을 잡았다.** 안 고쳤으면 9.2% 의 패널에서 자가검사가
  무너진다(A/B 출력 §2-7).
- **근거 사진 id 를 요소마다 붙였고, 근거 없는 요소는 넣지 않았다.** 스피커 구멍·
  측면 버튼을 봤지만 뺐다는 보고가 코드와 일치한다(grep 0건).
- **모르는 것을 모른다고 적었다.** 가로형 band_w 갭, 밴드 대비 초과를 스스로
  드러내고 AC 밖이라고 밝혔다.
- 카드가 건드리지 말라고 한 것을 하나도 건드리지 않았다(§2-9).

## 6. 수정안 (§8 에서 적용·재검증됨)

지적 1·2 는 기계적이고 범위가 분명하다. 두 패치의 내용은 아래와 같고,
실제 적용과 재검증은 §8 에 있다. 기존 커밋을 rebase·amend 하지 않았다.

### 패치 A — `synth_panel.py`, 밴드 높이 클램프 (지적 1)

`max_w` 클램프 블록 바로 뒤, `cx = rng.uniform(...)` 앞:

```python
    # 높이도 유리 안에 들어와야 한다 — band_h 의 분모가 캔버스(H)라 몸체 스트립이
    # 깊은 가로형에서 쿼드가 유리보다 높아져 아래쪽 몸체로 넘쳤다(리뷰 2026-09-12:
    # wide 3/52, 최대 24px). 폭 클램프(max_w)는 이것을 잡지 못한다.
    max_h = max(8, min(int(ph * 0.96), ph - 8))
    if dh + 2 * pad_y > max_h:
        s2 = max_h / (dh + 2 * pad_y)
        dh, glyph_w, pitch, gap = (int(dh * s2), int(glyph_w * s2),
                                   int(pitch * s2), int(gap * s2))
        pad_y = max(2, int(pad_y * s2))
        field_w = n_vis * pitch - gap
```

검증:
```

클램프 발동: portrait 0/549  wide 4/51                    (세로형은 한 장도 건드리지 않는다)
```

세로형 AC#7 은 구조적으로 영향이 없다(클램프가 발동하지 않는다). 가로형 band_h 는
조금 줄지만 가로형은 이미 AC 밖이고(실사진 0.798 vs 합성 0.708), **라벨이 유리를
넘지 않는 쪽이 옳다.**

고친 렌더러 300장 측정:
