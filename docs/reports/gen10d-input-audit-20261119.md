## 0. 결론 요약

재검증 대상 설명(**원인 가설**):

> "합성 프레임(896×516)이 640 레터박스에서 **업스케일**되어 밴드가 비정상적으로
> 크게 학습됨 — 실사진(다운스케일)과 스케일 관계가 반대"
> — `docs/reports/dc238-judge-2026-11-16.md` GEN10D 절 · `docs/MODEL_HISTORY.md` §7·§8

**관측과 가설을 가른 결과:**

| 항목 | 판정 |
|---|---|
| 관측: GEN10D 성적 81/4(정닥 −35, 확신도차단 폭증) | **확인** — 본 감사가 정확히 재현(§4) |
| 가설: 640 레터박스에서 "업스케일" | **반박** — 업스케일 0건/12,000. 최대변 896 프레임은 640에서 r=0.714 균일 축소(§2) |
| 가설: "밴드가 비정상적으로 크게" 학습 | **반박** — 캔버스 점유 분수는 416↔640에서 수학적으로 불변(실측 최대차 0.0). 밴드 픽셀은 정확히 640/416=1.5385배일 뿐 |
| 가설: 실사진과 "스케일 관계 반전" | **반박** — 합성:실촉 밴드 크기비(중앙) 0.975가 416·640 양쪽에서 동일. 반전 없음(§2) |
| 하락의 실제 소재 | **검출기가 아니라 리더.** 2×2 교차에서 리더만 바꾸면 116→82/94/81(−22~−35), 검출기만 바꾸면 116→117(+1)·오답 4→3·검출게이트실패 29→18(§4) |
| 새 관측: ps10d 검출기 + ps10b 리더 = 117/3 | **후속 측정으로 기각(§5-2)** — 함정 통과 16/31(51.6%)으로 승자 불가. GEN10B@640 승자 유지 |

즉 **"640 네이티브 학습이 기각됐다"는 결론의 관측(성적)은 살아 있으나, 적힌
원인 설명은 세 요소(업스케일·비정상 크기·관계 반전) 전부 코드·데이터와 어긋난다.**
하락을 만든 것은 리더(ps10d_rdr)이고, 검출기(ps10d_det640)는 DC238 검출 지표에서
오히려 승자 조건(ps10b@640)보다 좋다.

## 1. 검증 대상의 실체 — 체크포인트·코퍼스 (확인)

체크포인트 저장 인자 직접 추출(`torch.load`, `band_out/*.pt`):

```text
ps10b_det_neg25  {width 1.5, size 416, steps 2250, n_images 36000, seed 20260930,
                  grow 0.06, aug True, aug_scale_min 0.55, stride 16}
ps10d_det640     {width 1.5, size 640, steps 2250, n_images 36000, seed 20260930,
                  grow 0.06, aug True, aug_scale_min 0.55, stride 16}
```

→ size 외 전부 동일. **A/B는 깨끗하다**(문서 주장 "같은 GEN10B 데이터" 확인).

코퍼스 `synth_coco/GEN10B_TRAIN/annotations/instances_train2017.json` (n=36,000):

- 프레임 크기: **896×H 가변(221~580) 18,108장 + 896×896 정사각(음성) 17,892장**.
  높이 중앙값 514. 전 프레임 최대변 896.
- "896×516"은 실존하는 단일 크기가 아니라 근사 중앙값 표기(510~522 구간은
  72장뿐). 감사에는 영향 없음(전 프레임이 최대변 896으로 같은 변환을 받으므로).
- 밴드 bbox(원본 프레임 좌표): h 중앙 147.1px · w 중앙 198.6px (n=12,000).

변환 코드(`train_band.py:31` `letterbox`): `r = min(size/h, size/w)` — **긴 변
맞춤 축소만 존재**. 증강(`__getitem__`): 프레임을 sc∈U(0.55,1.25)로 축소 후 원 크기
캔버스에 얹고 레터박스. 최종 밴드 픽셀 = 원본밴드 × sc × r.

## 2. 같은 이미지·같은 증강의 416/640 짝측정 (반박의 근거)

방법: 주석 12,000양성 전수에 대해 결정적 시드로 sc를 뽑아 **같은 sc를 두 크기에
공유**(짝측정)하고 정본 `letterbox`와 같은 식으로 변환 후 밴드 크기를 잼.
실촉 대조는 DC238 값 207장의 사람 밴드 쿼드(프레임 크기는 실제 파일 EXIF 지향
판독 — `eval_real_judge.load_oriented` 관례. `ow/oh` 필드는 56행에만 존재해 사용
불가). 구현-산수 일치는 실제 이미지 20장 로드로 검증(밴드높이 차 0.0px).

**A1 — 합성 12,000장**

| | 416 | 640 |
|---|---|---|
| 레터박스 r (p10/중앙/p90) | 0.50 / 0.50 / 0.50 | 0.71 / 0.71 / 0.71 |
| 밴드 높이 px (p10/중앙/p90) | 36.4 / 59.9 / 95.1 | 56.0 / 92.1 / 146.3 |
| 밴드 폭 px | 54.6 / 83.7 / 127.3 | 84.1 / 128.7 / 195.9 |
| 캔버스 대비 밴드높이 분수 | 0.10~0.2 (중앙 0.14) | 0.10~0.2 (중앙 0.14) |
| 전체 스케일 sc×r 최대 | 0.580 | **0.893** |
| **업스케일(sc×r ≥ 1.0) 건수** | **0** | **0** |

- 밴드 픽셀비 640/416: 전 행 **정확히 1.5385**(min=max). 캔버스 점유 분수
  최대차 **0.0** — 두 크기에서 상대 크기는 완전히 같다.
- "업스케일"은 존재하지 않는다. 640에서도 전 부분 다운스케일(≤0.893).

**A2 — 실촬 DC238 값 207장**

| | 416 | 640 |
|---|---|---|
| 밴드 높이 px (p10/중앙/p90) | 42.5 / 61.4 / 90.2 | 65.4 / 94.5 / 138.7 |
| 밴드 폭 px | 59.1 / 81.9 / 115.4 | 90.9 / 126.0 / 177.5 |

**A3 — 합성:실촉 밴드 크기비(중앙값)**

| | 416 | 640 |
|---|---|---|
| 합성 중앙 / 실촉 중앙 | 59.9 / 61.4 = **0.975** | 92.1 / 94.5 = **0.975** |

→ 두 크기에서 비가 동일. **"스케일 관계 반전"은 없다.** (합성 밴드가 실촉과
거의 같은 픽셀 크기로 학습됐다는 뜻이기도 하다 — 옛 주석의 "합성이 실촬보다
2.3~4배"는 셀렉트스타 코퍼스 기준이고 DC238 기준은 아니다.)

## 3. 리더 학습 입력(크롭) 분포 — 차이 없음

`band_out/ps10b_det_neg25_crops.jsonl` vs `ps10d_det640_crops.jsonl`(검출기 제안
상자, 원본 프레임 좌표):

| | ps10b(416) | ps10d(640) |
|---|---|---|
| 양성 크롭 수 | 3,999 | 3,998 |
| 크롭 폭 px (p10/중앙/p90) | 180.6 / 233.6 / 311.6 | 180.8 / 234.2 / 312.8 |
| 크롭 높이 px | 119.6 / 172.3 / 249.0 | 120.2 / 172.5 / 250.0 |

→ 크롭 기하 분포는 사실상 동일. **리더 입력의 크기 분포 탓이라는 설명도 성립하지
않는다**(rdr10d 소심화의 원인은 §5 미확정로 남김).

## 4. 검출기 vs 리더 — 2×2 교차 (하락의 소재 분리)

체인·게이트·버킷은 `eval_real_judge.py` 본체와 동일 규칙(검출 0.25·면적 2% →
판독 → 값검증 10~600 → 최약자리 0.85). 값 207장.

| 검출기 + 리더 | 정닥 확정 | 오답 확정 | 검출게이트실패 | 확신도차단(판독정답) |
|---|---|---|---|---|
| ps10b@416 + rdr10b | 116 | 6 | 30 | 18 |
| **ps10b@640 + rdr10b (승자)** | **116** | **4** | 29 | 21 |
| ps10b@416 + rdr10d | 82 | 9 | 30 | 50 |
| ps10b@640 + rdr10d | 94 | 5 | 29 | 41 |
| **ps10d@640 + rdr10b** | **117** | **3** | **18** | 29 |
| ps10d@640 + rdr10d (GEN10D) | 81 | 4 | 18 | 59 |

**앵커 재현**: 본 감사 하니스는 문서 기록 3개를 전부 정확히 재현한다 —
GEN10B 116/6 · GEN10B@640 116/4 · GEN10D 81/4(+게이트실패 18·확신도차단 59,
`dc238-judge` 807행과 항목별 일치). 재현성 사고(§6 재현성 규칙) 없이 1회 실행.

읽는 법:

- **리더만 교체(rdr10b→rdr10d)**: 116→82(@416) · 116→94(@640) · 117→81(@640).
  확신도차단(판독정답)이 18~29→50~59로 폭증 — 문서가 GEN10D의 특징으로 적은
  "확신도차단 폭증"은 리더의 성질이다.
- **검출기만 교체(ps10b@640→ps10d@640)**: 정닥 +1, 오답 −1, 검출게이트실패
  29→18. 검출기 단독 지표(§C): 게이트 통과율 87.4%(416) → 95.2%(승자 조건) →
  **98.1%(ps10d)**, 통과 상자 GT-IoU 중앙 0.8으로 동일.
- 결론: **GEN10D의 정닥 폭락(−35)은 전적으로 rdr10d가 만들었고, ps10d 검출기는
  해를 끼치지 않았고 오히려 실사진 검출은 더 잘한다.**

## 5. 미확정

1. **rdr10d가 소심해진 원인.** 크롭 기하 분포는 동일(§3), 리더 체크포인트에는
   epoch/acc만 기록(둘 다 학습셋 acc=1.0 수렴, best 에폭 51 vs 49)되어 학습 인자
   동일성을 체크포인트로 확인 불가. 새 학습 금지 범위 밖이라 원인 특정 없음.
   후보(검증 안 됨): 제안 상자의 내용적 미세차, 학습 배치 순서·시드.
2. **ps10d@640 + rdr10b = 117/3의 함정(31장) 축.** → **후속 측정으로 해소
   (2026-11-19, 같은 날)**: `audit_gen10d_trap.py`가 같은 6조합으로 함정
   31장을 짝측정(`audit_gen10d_trap_out.json`). 결과 — 함정통과: 승자
   ps10b@640+rdr10b **9/31**, ps10d@640+rdr10b **16/31(최악)**, GEN10D
   재현 ps10d@640+rdr10d 11/31(문서 기록 12·11·8과 항목 일치 — 앵커 재현).
   **결론: "117/3 조합"은 함정 축에서 기각 — 값 리콜 향상(게이트 실패
   29→18)과 함정 통과 악화(9→16)가 같은 검출기의 양면. GEN10B@640
   (116/4/9) 승자 유지.**
3. **오답 3 vs 4(§4)** — n=207에서는 구분 불가(관측 차이일 뿐).
4. 문서 표기 "896×516"(raw 로그·MODEL_HISTORY §7) — 실제는 896×H 가변+정사각
   (§1). 정정 가치는 있으나 결론에는 무관.

## 6. 제약 준수·재실행

- 새 학습·생성기 수정·앱/ONNX 교체·의존성 변경·기존 결과 덮어쓰기 **전부 없음**.
  검출기 교차는 체크포인트의 `size` 필드만 바꿔 임시 파일로 추론(가중치 불변,
  종료 시 삭제). 산출물: 신규 3종(스크립트·JSON·본 보고서)만.
- 재실행(전체, melotts env):
  `conda run -n melotts python audit_gen10d_input.py`
  (기하·크롭만: `--skip-det`. 소요 ~15분, GPU 1회)
- 후속 함정축 교차: `conda run -n melotts python audit_gen10d_trap.py`
  (§5-2 해소 측정, 원시 `audit_gen10d_trap_out.json`)
- 리더 인자 확인 명령(§5-1의 근거): `conda run -n melotts python _audit_reader_args.py`
- 원시 수치 전체: `audit_gen10d_input_out.json`(A1~A4·B·C·D 전 버킷).
