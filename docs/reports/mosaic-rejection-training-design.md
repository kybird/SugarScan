# 모자이크 오확정 방지 학습 설계

2026-11-14 Codex 제안. 대상은 현재 mg/dL 경로의 BandNet과 CRNN이다. [Android 재현 기록](../../doc/raw/2026-11-14.md#case-1-배포-bandnet과-crnn에서-비혈당계-무늬가-값-후보를-만든다)에서 숫자가 없는 사각형 무늬가 확인 화면을 열었다. 목표는 이 오확정을 줄이면서 실제 혈당계의 정답 확정률을 유지하는 것이다.

## 1. 데이터

새 학습은 합성 데이터와 자체 초기화로 진행한다. 현재 번들은 제품 비교용으로 평가한다. 실제 사진과 카메라 클립은 평가에 사용한다. 실제 사진으로 음성 채굴·체크포인트 선택을 반복하면 독립 검증셋이 오염되므로, 채굴은 합성 train 안에서만 한다.

| 프레임 | 검출 타깃 | 판독 타깃 |
|---|---|---|
| 정상 LCD와 경쟁 무늬가 함께 있음 | 실제 혈당 숫자 밴드 하나 | 숫자가 전부 보이는 검출 크롭에 정답 문자열 |
| 혈당계 없는 모자이크·격자·인쇄 문자·일반 숫자·디지털 시계 | 상자 없음 | 검출이 잘못 만든 크롭은 빈 문자열 |
| 꺼진 LCD, 표시는 켜졌지만 숫자가 전혀 없음 | 상자 없음 | 빈 문자열 |
| 프레임에 정상 LCD가 있으나 검출 크롭이 숫자를 잘라냄 | 원본 프레임의 올바른 밴드 상자 | 잘린 크롭은 빈 문자열 |
| 가림이나 프레임 경계 때문에 물리적으로 읽을 수 없는 LCD | 숫자 일부가 없다는 생성기 근거가 있는 경우에만 음성 | 빈 문자열 |

- 양성은 기존 합성 코퍼스의 패널과 전체 기기를 사용한다. 가까움·멀리 있음, 흐림, 반사, 노출 및 배경 경쟁 무늬를 포함한다. 혈당계가 없는 음성과 양성의 배경·압축·회전·해상도 범위를 공유해 배경색만 외우는 것을 막는다.
- 음성은 사각형 무늬의 크기·밀도·대비·회전, 문자 폰트와 배열, 화면 UI와 숫자 배열을 다양화한다. 단색 프레임도 대조군으로 둔다. 애매하게 읽히는 양성은 자동으로 빈 라벨을 붙이지 않는다. `HI/LO`는 이 숫자 전용 경로에서 별도 거절 평가층으로 둔다.
- 장면 원본·기기/폰트 템플릿·무늬 생성 계열·촬영 세션을 기준으로 분리한 뒤 변형을 만든다. 같은 사진의 합성 변형이나 같은 클립의 프레임은 한 split에 묶는다. 기존 재현 이미지와 28장 진단 세트는 고정 회귀 검사로 보존하고, 독립 검증은 새 장면에서 한다.
- 매니페스트에 장면 그룹과 시드, 양성/음성 사유, 각 숫자의 가시 영역, 원본에서 실제 검출된 crop 좌표, 검출기 체크포인트 해시를 남긴다. 전체 글자 가시 여부는 생성기에 있는 글자별 영역을 활용한다. 애매한 크롭은 학습 라벨에서 제외하고 진단에 남긴다.

## 2. 검출기 학습

`CocoBand`는 명시적으로 음성으로 표기된 이미지도 읽고 `has_band`를 넘긴다. 라벨 누락 데이터는 입력 검증 오류로 분리한다. 음성은 objectness 맵 전체가 0이고 박스 회귀 손실은 0이다. `assign_targets`의 최소 1개 양성 셀 보정은 양성 이미지에만 적용한다. 가짜 0면적 상자로 음성을 표현하면 이 보정이 배경을 양성으로 가르칠 수 있다.

음성 objectness 손실은 프레임별로 정규화하고, 높은 점수를 받는 배경 셀도 손실에 기여하도록 한다. 모든 셀을 독립 프레임처럼 더해 양성 손실을 압도하지 않도록 양성·음성 손실을 따로 기록한다. 처음에는 배치의 음성 비중을 25%로 두고 다양한 음성을 섞는다. 이후 초기 체크포인트가 높은 점수를 준 합성 음성을 재샘플링하되, 같은 무늬만 반복하지 않도록 랜덤 음성을 유지한다.

## 3. 판독기 학습

리더에는 검출기가 실제로 제안한 상자를 앱과 같은 방식으로 자르고 144×96으로 넘긴다. 양성 학습 크롭은 해당 장면 그룹을 보지 않은 검출기에서 생성한다. 음성 학습 크롭은 검출기를 속인 모자이크·문자와 숫자가 잘린 크롭에서 얻는다. 리더 검증 입력은 별도 장면에서 생성한다.

첫 실험에서는 현재 숫자 10종 + CTC blank 출력을 유지한다. 음성 크롭은 빈 타깃(길이 0)으로 학습해 모든 타임스텝이 blank인 출력을 유도한다. 양성·음성 loss를 별도로 평균내고 가중을 기록한다. 본학습 전에 양성 혼합 배치와 음성만 있는 배치에서 유한한 손실·그래디언트가 나오고, blank 출력이 앱에서 `noTextFound`가 되는지 확인한다. 빈 타깃 학습을 넣고도 높은 확신의 오확정이 남으면, 별도 판독 가능 여부 헤드를 후속 실험으로 비교한다.

## 4. 실험 행렬

| 조합 | 검출기 | 리더 | 확인할 것 |
|---|---|---|---|
| 제품 기준선 | 현재 번들 | 현재 번들 | 동일 입력에서 제품 수준 비교 |
| 합성 기준선 | 합성 양성만 | 합성 양성 크롭만 | 새 학습 계보의 기준 |
| 검출기만 변경 | 합성 양성·음성 | 합성 기준선 리더 | 배경 거절 개선과 실제 밴드 미검출 |
| 리더만 변경 | 합성 기준선 검출기 | 양성·빈 타깃 | 동일 크롭에서 거절 학습 효과 |
| 둘 다 변경 | 합성 양성·음성 | 이 검출기의 교차검증 크롭과 빈 타깃 | 최종 조합의 추가 개선과 양성 회귀 |

초기 비교는 같은 시드·양성 샘플 노출 횟수·양성 증강·모델 크기·업데이트 횟수를 맞춘다. 음성은 별도 배치 부분으로 추가하고 계산량 차이도 기록한다. 검출 입력 크기와 리더 구조, 앱의 임계값을 고정한다. 유망 조합은 추가 시드 2개에서 반복한다. 검출기의 박스 변화와 리더 학습 효과를 구별하기 위해 동일 크롭 묶음에서도 리더 둘을 비교한다.

## 5. 채택 판정

1. **합성 독립 검증**에서 음성 유형별로 상자 통과, 숫자 후보 발생, 확인 화면 도달을 단계별로 센다. 양성에서는 정답 확정·오답 확정·미확정과 글자 잘림을 기기·거리별로 센다. 임계값 스윕은 검증 split에서만 하고 동결 후 테스트한다.
2. **동일한 실제 평가 입력**으로 번들과 새 조합을 짝비교한다. 음성은 모자이크, 일반 문자·숫자, 꺼진 LCD를 포함한다. 양성은 기기별·거리별 정답 확정과 새로 발생한 오답/미확정 건을 공개한다. 기존 정지 사진 결과와 라이브 결과는 각각 보고한다.
3. **Android**에서는 동일 이미지 가져오기와 라이브를 따로 실행한다. 사진 가져오기의 규칙 엔진용 슬롯 전처리 성공 여부를 기록한다. 라이브는 고정 길이 클립에서 실제 앱의 안정화까지 실행한다. 음성 분모는 프레임 수가 아니라 독립 클립/장면 수다. 양성은 첫 정답 확정까지의 시간도 본다.

채택 조건 제안은 재현 모자이크의 오확정 제거, 독립 음성에서 오확정 감소, 실제 양성에서 새 오답 확정 0건이다. 허용할 정답 확정률 하락 폭과 실기기 평가 규모는 후보 결과를 보기 전에 정한다. 작은 표본의 0건은 검증한 표본의 결과로만 보고한다. 번들 교체는 양성과 음성의 짝비교와 Android 실측 이후 결정한다.
