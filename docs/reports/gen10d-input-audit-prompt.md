# GEN10D 입력 경로 재검증 — 작업자 지시서

아래 블록을 그대로 전달한다. 측정 작업이며 새 모델 설계·학습 승인은 아니다.

```text
작업 위치: D:\Project\sugarScan
작업 ID: G-GEN10D-INPUT-AUDIT-20261119

목표
GEN10D 성능 하락의 원인으로 기록된 "896×516 합성이 640 레터박스에서 업스케일된다"를 실제 입력 경로로 검증한다. GEN10D 성능 하락이라는 관측과 원인 설명을 분리한다. 고해상도 렌더가 필수라는 결론을 전제하지 않는다.

먼저 읽을 것
CLAUDE.md, docs/SPEC.md, docs/MODEL_HISTORY.md, docs/GLM_TASKS.md §1~§3, docs/reports/dc238-judge-2026-11-16.md의 GEN10B/C/D 절, docs/reports/status-2026-11-19.md.
llm-wiki search로 metric-provenance, stale-baseline-quoted-as-current, metric-path-not-under-test 관련 기록을 확인한다. 폐기 페이지는 대체 문서를 따른다.

1. 산출물과 실행 설정부터 확인한다.
GEN10B와 GEN10D의 체크포인트, 코퍼스, 생성 계획, 검출기 학습 로그, reader boxes, 리더 학습 로그, 평가 JSONL의 실제 위치와 존재 여부를 조회한다.
현재 로컬에는 band_out/ps10b_det_neg25.pt와 reader_out/ps10b_rdr/best.pt가 없었던 이력이 있다. 다른 경로를 추측하거나 비슷한 이름의 모델로 대체하지 않는다. 누락 항목과 수행 가능한 범위를 먼저 보고한다.
체크포인트 해시, 코드 커밋, 생성·학습 시드, 입력 크기, batch, optimizer update 수, 양성/음성 노출 수, epochs, jitter/augmentation, grow, 리더 크롭 생성에 사용한 검출기와 해상도를 확인한다. 문서에 적힌 설정과 실제 실행 설정을 구분한다.

2. 기존 자를 찾아 사용한다.
assets_dev/train/measure_panel_stats.py, train_band.py, make_reader_boxes.py, reader_crnn.py, eval_real_judge.py, probe_multisize.py를 읽는다.
기존 자가 이 측정을 지원하면 확장 또는 재사용한다. 지원하지 않는 항목만 재실행 가능한 진단 스크립트로 추가한다. 즉석 스크립트 출력만 보고서에 인용하지 않는다. 새 자는 버전 관리 대상에 포함하고 보고서에 정확한 명령을 남긴다.

3. 같은 이미지와 같은 증강 표본을 416/640 입력에 짝지어 측정한다.
원본 파일의 실제 W/H, 기하 증강 직후 W/H, letterbox r/dx/dy, 변환 후 이미지 W/H를 기록한다.
정답 밴드의 원본 높이/폭, 변환 후 높이/폭(px), 프레임 대비 면적비, stride 16 기준 높이/폭(칸)을 기록한다.
기하 증강의 배율과 원본→증강→letterbox의 합성 배율을 분리한다. r>1인 업스케일 여부와 416보다 640에서 상대적으로 크게 보이는 현상을 혼동하지 않는다.
증강 끔과 실제 학습 설정의 증강 켬을 분리한다. 난수 시드와 이미지 목록을 고정하고, 416/640에서 같은 이미지·같은 변환을 사용한다. 실행 중인 학습 프로세스의 난수나 소스를 변경하지 않는다.
가능하면 메타데이터는 전량 집계한다. 디코드·증강 표본은 기기/프로파일 층을 포함해 고정 목록으로 뽑고, 층별 n과 표본 추출 방법을 적는다. 소수 예시를 모집단 통계로 말하지 않는다.
결과는 p10/중앙/p90, 업스케일 건수와 분모 n, 이미지별 CSV/JSONL로 남긴다.
실사진의 정답 밴드 비교는 사람 밴드 라벨이 실제로 있는 사진만 사용한다. 라벨이 없으면 정답 밴드 크기를 추정해 채우지 않는다. 예측 박스 크기는 별도 지표다. 실사진은 평가에만 쓴다.

4. 산출물이 있을 때만 검출기와 리더 사이를 추가 분해한다.
같은 평가 사진에서 GEN10B/GEN10D의 검출 점수, 실제 크롭, 판독 문자열, 자리별 확신도, 최종 탈락 단계를 짝지어 비교한다.
각 검출기 크롭과 각 리더의 2×2 조합을 평가해 검출기 변화와 리더 변화가 섞이지 않게 한다. 입력 해상도는 명시적으로 고정한다.
사람 밴드 크롭을 사용하는 경우 진단 전용으로 별도 표시하고 배포 성능에 섞지 않는다.
문턱과 채점 규칙은 동결한다. 임계값을 맞춰 기존 성적을 재현하지 않는다. 반복 실행 결과가 흔들리면 모든 실행을 남기고 변동 폭과 환경을 보고한다. 기준점과 일치한 실행만 골라 보고하지 않는다.
현재 probe_multisize.py는 출력 파일명이 고정되어 있으므로 기존 결과를 덮어쓰지 않도록 별도 출력 경로를 지원하거나 안전한 별도 실행 디렉터리를 사용한다.

금지 사항

다른 작업자의 변경을 되돌리지 않는다. 실사진을 학습에 넣지 않는다. 학습이 필요한 후속 가설은 제안만 하고 멈춘다.

산출물과 완료 기준
docs/reports/gen10d-input-audit-20261119.md에 실제 명령, 환경·해시, n, 표본 목록, 원시 결과 위치, 짝비교 표, 누락·미실행 항목을 적는다.
결론을 "측정으로 확인", "반박", "아직 모름"으로 구분한다. 업스케일 가설, 밴드 화소 크기 분포 변화, 크롭 분포 변화, 리더 확신도 변화를 따로 평가한다. 원인까지 입증하지 못하면 원인 미확정이라고 쓴다.
측정과 모순되는 문서 설명은 관측 결과를 보존하면서 정정하고, 위키 원기록은 삭제하지 않고 정정 근거로 연결한다. 고해상도 렌더는 필요성을 입증했을 때만 후속 실험 후보로 제시하며 필수라고 단정하지 않는다.
구문 검사와 작은 고정 표본의 좌표 변환 검증을 수행한다. 새 측정 스크립트는 커밋하고 보고서에서 재실행할 수 있어야 한다. 모델 설계나 실험 예산 결정이 필요해지면 진행하지 말고 판단 요청으로 올린다.
```
