# G12 — l10n 정합성을 테스트로 고정

- 브랜치: `glm/G12-l10n-consistency`
- 커밋: 이 보고서와 함께 하나
- 상태: 완료

## 무엇을 했나

`test/l10n/arb_consistency_test.dart` 신규 — ARB 파일을 **파일에서 직접** 읽어
(`dart:io` + `dart:convert` 만, 새 패키지 없음) 다섯 검사를 돌린다:

1. ARB 파일이 정확히 6개(en·ko·es·pt·de·fr)다.
2. **6개 ARB 의 키 집합이 완전히 같다** — 빠진 키는 파일 이름과 키 목록을
   찍어 실패시킨다("개수가 다르다"만으로는 찾게 아니라는 지시서 요구).
3. **번역본에 키 메타데이터가 없다** — `@@locale` 은 파일 규격의 로케일
   선언이라 제외(아래 "왜" 참조).
4. **플레이스홀더가 파일 간에 일치한다** — 키마다 `{name}` 집합을 영문
   원본과 대조. 한 언어에서만 빠지면 gen-l10n 을 통과해도 런타임에 그 언어만
   깨진다.
5. **`lib/` 어디에서도 참조되지 않는 키가 없다** — 게터 이름(키의
   snake→lowerCamel 변환, 현재 키는 전부 camelCase 라 사실상 항등)을
   `lib/` 소스(`lib/l10n/generated/` 제외)에서 정규식 검색.

## 왜 그렇게 했나

- 지시서는 4검사였는데 파일 목록 확인(1번)을 덧붙였다 — 언어를 추가할 때
  ARB 를 늘리고 이 테스트의 기대 목록을 안 고치면 2번 검사가 대신 잡지만,
  그 실패 메시지("파일이 정확히 6개다")가 원인을 더 직접적으로 말한다.
- `@@locale` 제외: 지시서 문구는 "번역본에 `@` 메타데이터가 없다"인데, 현재
  6개 파일 모두 `@@locale` 을 담고 있다(실측). 이것은 키 설명이 아니라 ARB
  규격의 파일 수준 로케일 선언이고 gen-l10n 이 쓴다 — 키 메타데이터(`@key`)
  만 원본 단독으로 제한하는 것으로 읽었다. 다르게 읽어야 하는지는 사람
  판단으로 남긴다.
- 게터 이름 변환을 넣은 이유: 키 추가 관례가 언젠가 snake_case 로 바뀌어도
  이 테스트가 조용히 오탐을 내지 않게 하려는 방어다.
