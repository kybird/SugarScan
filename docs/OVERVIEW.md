# SugarScan — 무엇을 푸는 저장소인가

다른 에이전트(및 사람)가 이 저장소 전체를 빠르게 이해하기 위한 진입 문서.
작성 2026-11-19. 규칙은 `CLAUDE.md`, 모델 여정은 `docs/MODEL_HISTORY.md`가
정본 — 이 문서는 **문제 정의와 전체 그림**만 담는다.

## 한 문장 정의

**일반 혈당계(SMBG)의 LCD 숫자를 카메라로 읽어 기록하는 Flutter 앱.**
사용자는 혈당계를 찍거나 갤러리에서 고르고, 앱이 숫자를 읽어 확인 시트를
내놓고, 사용자가 1탭으로 확인하면 기록으로 저장된다.

## 문제의 네 겹 — 왜 이게 단순 OCR이 아닌가

**1. 7-세그먼트 LCD는 일반 OCR이 못 읽는다.**
혈당계 숫자는 세그먼트 폰트다 — 일반 인쇄 문자 학습 모델이 그대로 실패한다.
여기에 LCD 고유의 난제가 겹친다: 유리 반사·주름 글레어, 꺼진 자리의 고스트
세그먼트(은은한 8), 기기별 극성 반전, 세로형/가로형 레이아웃, 기기별 숫자
종횡비. 게다가 혈당계는 액정이 아니라 **코드 화면·시각 화면** 등 다른 모드를
갖는다 — 숫자가 보이는 화면이 전부 혈당 값은 아니다.

**2. 학습 데이터를 구할 수 없다.**
혈당 수치는 민감정보이고, 실사진 데이터셋은 라이선스(Ultralytics 계열
AGPL, Selectstar CC BY-SA 등)나 권리 사슬 문제를 일으킨다. 그래서 내린
결정: **학습에 실사진 0장** — 전부 합성 생성기로 굽는다. 대가는
**합성→실제 도메인 간극(sim-to-real domain gap)** 이고, 이것이 이 저장소의
중심 기술 난제다. 실사진은 재판(판정)에만 쓴다(DC238, CC0, 238장).

**3. 틀리면 안 된다 — 그러나 못 읽는 것도 허용된다.**
의료 인젝 데이터다. 설계 목표는 "오답 확정 ≤5% 안에서 정닥 확정 최대"
(selective prediction — 거부 가능한 예측). 인식은 자동이어도 **저장은
사용자 확인 1탭**이며, 모델이 못 읽으면 수동 입력 경로가 항상 열려 있다.
진단성 문구("정상/위험")·인슐린 계산은 금지 — 일반 건강관리 도구 분류 유지.

**4. 단말에서만 돈다.**
OCR은 전부 온디바이스(ONNX Runtime). 네트워크 엔진은 등록 자체가 거부된다.
오프라인에서 온전히 동작해야 하고, 서버(Supabase, 선택)는 기록 동기화만.

## 시스템 그림

```
[앱 Flutter]  features/ → ocr/ (격리 모듈) → domain/ (순수 Dart)
                    ↓                          ↑
                 data/  → Drift(정본) + 아웃박스 → Supabase(복제본, 선택)
```

- **OCR 모듈 경계**: 앱은 `lib/ocr/ocr.dart` 배럴만 본다. 글자 보정·값
  검증·프레임 합의가 모두 모듈 안에서 끝나고 `ScanConfirmed`가 나오면
  "쓸 수 있는 값"이다. 앱은 재검증하지 않는다.
- **두 스캔 경로**: 카메라 실시간(가이드박스가 크롭 → 리더 직행) /
  사진·갤러리(전체 사진 → 밴드 검출기 → 크롭 → 리더).
- **모델 체인**: BandNet 검출기(1.1M) → CRNN 판독기(2.3M) → 값 검증
  (10~600 mg/dL) → 최약 자리 확신도 0.85 → 사용자 확인. 자세한 설계·세대별
  성적은 `docs/MODEL_HISTORY.md`.

## 판정 체계 — "좋아졌다"를 어떻게 아나

- **정답표**: DC238 238장(값 207·함정 31) — 유일한 실사진 재판 세트.
- **채점기**: `assets_dev/train/eval_real_judge.py` — 앱 확정 규칙 그대로
  시뮬레이션, 성적은 **앱 실제 확정**(모든 게이트 통과)만 센다.
- **현재 최적**: GEN10B@640 — 정닥 56.0% · 오답 1.9% · 함정 29.0%
  (참조점인 실촉 파인튜닝 제품: 69.7% · 6.6% · 40.0%).
- 숫자를 문서에 인용할 때는 그 숫자를 낸 자(스크립트)를 함께 남긴다
  (`CLAUDE.md` "수치를 인용하기 전에" 절).

## 다음에 올 에이전트가 가장 흔히 틀릴 것

1. "실사진을 조금만 파인튜닝에…" — 금지. 유일 경로는 합성기 강화 루프.
2. "코드 화면을 검출기에 음성으로 넣자" — GEN6~8에서 3연패. 검출기는
   숫자줄만; 문맥은 프레임 층 분류기(미착수)나 뒷단 게이트의 몫.
3. "게이트/문턱을 손보면 되겠다" — 전부 측정 종결(MODEL_HISTORY §8).
4. 옛 실험 수치(gmscreen 계보, 2026-09-17 이전)를 근거로 인용 — 폐기됨.
5. 학습 중인 소스 파일 수정 — 직후 import하는 재판 프로세스가 죽는다.
