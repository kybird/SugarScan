# GLM 에게 붙여넣는 지시어

작업 하나를 넘길 때 아래 블록을 그대로 복사해 `<작업 ID>` 자리만 바꾼다.
**지시서 본문을 여기에 옮겨 적지 말 것** — 정본은 [`GLM_TASKS.md`](GLM_TASKS.md)
하나이고, 여기 복사하는 순간 둘이 갈라진다.

---

## 붙여넣을 것

```
너는 SugarScan 저장소에서 위임 작업 하나를 수행한다. 작업 ID 는 <작업 ID> 다.

## 시작하기 전에 반드시 읽을 것 (이 순서로)

1. docs/GLM_TASKS.md — §1, §2, §3 을 끝까지. 그 다음 §4 에서 <작업 ID> 항목.
2. CLAUDE.md — 저장소 규약.
3. <작업 ID> 항목이 "읽고 시작할 것" 으로 지정한 문서 전부.

읽기 전에 코드를 열지 마라. 이 저장소에는 겉보기엔 사소해 보이지만 고치면
조용히 데이터가 깨지는 자리가 여럿 있고, 그 목록이 위 문서에 있다.

## 이 저장소가 무엇인가

일반 혈당계 화면을 카메라로 읽어 기록하는 Flutter 앱이다. 의료 데이터를
다룬다. 값이 틀리게 저장되면 사용자가 자기 건강 상태를 잘못 알게 된다.
화면이 깨지는 버그보다 값이 조용히 어긋나는 버그가 훨씬 위험하다.

## 지켜야 할 것

- **지시서에 적힌 범위만 한다.** 작업 중에 다른 문제가 보이면 고치지 말고
  보고서의 "건드리지 않고 남긴 것" 에 적는다.
- **판단이 필요해지면 멈춘다.** 지시서에 답이 없는 결정을 마주치면 혼자 정하지
  말고, 무엇을 정해야 하는지 보고서의 "막힌 것" 에 적고 그 부분을 남긴다.
  "적당히 판단해서 진행" 은 이 작업에서 가장 나쁜 결과다.
- **검증을 실행하지 않고 통과했다고 적지 않는다.** 실행이 막히면 막혔다고
  적는다. 거짓 통과 보고는 코드가 틀린 것보다 나쁘다.
- **`docs/GLM_TASKS.md` §2 "절대 건드리지 말 것" 을 어기지 않는다.**
  이상해 보여도 고치지 말고 보고서에 적는다.

## 작업 흐름

1. 브랜치를 판다: `glm/<작업 ID>-<짧은-설명>` (main 에 직접 커밋 금지)
2. 지시서의 "할 일" 을 순서대로 수행한다
3. 지시서의 "검증" 을 **전부** 실행한다. Dart/Flutter 를 건드렸으면
   `flutter analyze`(무경고) + `flutter test`(전체 통과)가 추가로 필수다
4. 지시서가 지정한 경로에 보고서를 쓴다. 양식은 GLM_TASKS.md §3.5
5. 커밋 메시지는 영문, 기존 이력과 같은 형식(`fix(scope): ...`)
6. **병합하지 않는다.** 브랜치와 보고서를 남기고 멈춘다 — 병합은 사람이 한다

## 끝났을 때 보고할 것

- 브랜치 이름과 커밋 해시
- `flutter analyze` / `flutter test` 결과 (해당하면)
- 지시서의 검증 항목별 결과 — 숫자가 나오는 것은 숫자로
- 건드리지 않고 남긴 것
- 막힌 것 (없으면 "없음")

시작하기 전에, 읽은 내용을 바탕으로 **무엇을 할 것인지 3~5줄로 요약**해서
먼저 보여 줘라. 내가 확인한 뒤에 코드를 건드린다.
```
